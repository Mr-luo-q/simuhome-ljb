# 投稿创新点总纲：从任务型智能家居 Benchmark 到连续家庭世界评测

本文档聚焦论文投稿时真正要主张的创新。技术架构、接口、时间核、MCP、Home Assistant 和 viewer 仅在它们能够支撑创新论证时出现，不作为并列创新罗列。

本文档的判断基于：

```text
mcp/doc/1-6
  HA MCP、外部方案、myserver 与工具边界的演进

mcp/doc/7
  空间化环境、长期主动服务、现实迁移三条研究主线

mcp/doc/8-10
  沙箱世界、时间机制、HA 接口边界和实施路线

重点相关工作
  HomeBench
  SimuHome
  PersonalHomeBench
  SMH-Bench
```

当前结论先写在最前面：

```text
最稳妥的投稿结构

核心创新一
  空间—时间一致的连续家庭世界 Benchmark

核心创新二
  面向长期共居的闭环主动服务评测

条件性贡献三
  虚拟环境到现实平台的语义迁移与成对评测

统一论文命题
  将智能家居 Agent 的评测单位
  从孤立任务提升为持续演化的家庭生活过程
```

第三项当前只能称为“条件性贡献”。如果最终只有统一接口和 HA demo，它属于工程支撑；只有完成成对任务、跨后端契约和迁移损失实验后，它才能升格为投稿创新。

---

## 1. 投稿要回答的总问题

四篇重点相关工作分别推进了设备控制、时间环境、个性化和能力覆盖，但它们的评测对象仍然相对分散：

```text
HomeBench
  重点测复杂指令能否正确执行

SimuHome
  重点测动态环境和时间调度

PersonalHomeBench
  重点测家庭上下文、个性化和主动推荐/规划

SMH-Bench
  重点测环境接地后的通用能力谱系
```

我们的论文需要进一步提出：

> 当家庭被建模为一个具有空间结构、连续时间、人物活动、环境变化和历史积累的生活世界时，智能家居 Agent 应该如何被评测？

这个问题比“再增加哪些任务类别”高一层。它改变了评测单位：

```text
已有常见单位
  一条指令
  一个任务
  一组静态家庭上下文
  一次计划或工具调用轨迹

我们提出的单位
  一个持续演化的家庭世界
  +
  Agent 在其中长期观察、行动、等待、记忆和服务的完整过程
```

因此，论文的核心概念建议统一称为：

```text
Continuous Household World Benchmark
连续家庭世界评测
```

“空间化”“长期主动服务”“虚实迁移”都是这一总命题的三个观察面，不要在论文里写成彼此无关的功能模块。

## 2. 相关工作的真实边界

### 2.1 HomeBench：规模和指令鲁棒性已经很强

HomeBench 的价值在于大规模设备控制、有效/无效指令和复杂多设备指令。它已经充分覆盖：

```text
单设备 / 多设备
有效 / 无效 / 混合指令
设备存在性与动作合法性
复杂自然语言到设备调用的映射
```

因此，“我们支持更多设备控制任务”很难成为有力创新。我们的差异必须落在空间因果、连续时间和长期生活过程上。

### 2.2 SimuHome：时间和环境动力学已经不能再被当作空白

SimuHome 已经包含：

```text
环境变量
离散 tick
设备作用持续生效
绝对时间调度
事件锚点调度
多设备协同调度
可行与不可行任务
```

所以“加入时间机制”“加入温度变化”“支持调度”都只能算承接。我们需要推进的是：

```text
空间拓扑进入世界本体
人物生活进入时间世界
多个 episode 被连接为长期共居过程
主动服务的收益与干扰被持续评测
```

### 2.3 PersonalHomeBench：个性化和主动性已经存在

PersonalHomeBench 已经测量家庭背景、个性化、主动推荐和计划生成。它的重要提醒是：

```text
“个性化”本身不是我们的独占创新
“主动推荐”本身也不是我们的独占创新
```

我们可以主张的推进点在于：

```text
PersonalHomeBench 的主动任务
  主要基于给定家庭上下文进行推荐或计划

我们的长期主动服务
  发生在连续时间世界中
  Agent 需要从多次事件中形成认识
  在状态持续变化时决定是否服务
  服务动作会改变后续环境与人物体验
  后续结果又会影响下一次决策
```

真正的差异关键词是：

```text
continuous
closed-loop
cumulative
```

### 2.4 SMH-Bench：能力覆盖和环境交互已经很完整

SMH-Bench 已经覆盖原子控制、组合控制、模糊意图、自动化、多轮、记忆和环境查询，并提供完全可观测与交互式两种评测模式。

所以“我们也有完整能力列表”缺少新意。我们的推进点应聚焦：

```text
空间关系参与任务可行性与指代解释
家庭状态在统一时间线上持续演化
人物活动和 Agent 服务构成长期反馈闭环
虚拟与现实后端接受成对迁移评测
```

### 2.5 四篇工作之后还剩下什么问题

```text
现有工作已经分别回答
  能否执行复杂控制指令
  能否处理动态环境和时间调度
  能否利用个性化家庭上下文
  能否覆盖通用智能家居能力

仍值得继续追问
  能否在一个空间—时间一致的家庭世界中长期服务
  能否从连续生活反馈中调整主动服务策略
  能否把这种策略迁移到现实智能家居平台
```

这三句就是本文后续创新点的来源。

## 3. 核心创新一：空间—时间一致的连续家庭世界 Benchmark

### 3.1 建议投稿表述

> 我们提出一种空间—时间一致的智能家居 benchmark 世界模型，将房间拓扑、设备位置、人物位置、环境动力学和任务事件置于同一持续演化的家庭世界中，并通过共享真相的 2D 执行表示与 3D 校准表示支持可扩展评测和空间有效性验证。

这项创新的核心不在 2D 或 3D 页面。核心变化是：

```text
空间从标签升级为可计算关系
时间从任务参数升级为世界演化轴
环境变化从结果字段升级为动作的持续后果
任务从独立样本升级为世界中的事件过程
```

### 3.2 为什么具有研究价值

很多智能家居指令看似是设备控制，实际依赖空间条件：

```text
“关闭我刚刚离开的房间里的灯”
  需要人物轨迹 + 房间转换 + 历史事件

“把离老人当前位置最近的取暖设备打开”
  需要人物位置 + 设备位置 + 可达关系

“卧室降温时不要让相邻婴儿房过冷”
  需要房间邻接 + 环境传播 + 副作用约束

“我去厨房后再打开排风”
  需要空间事件 + 时间条件 + 延迟动作
```

只有房间标签和设备列表时，这些任务要么无法定义，要么需要在文本里预先写出大量答案。连续家庭世界允许空间关系直接参与任务生成、执行和验证。

### 3.3 与 SimuHome 的关键差异

SimuHome 已经解决时间与环境演化，因此我们的创新不能写成“动态智能家居环境”。更准确的差异是：

```text
SimuHome 主线
  设备和环境随时间演化
  时间调度形成主要难度

我们的推进
  空间拓扑成为世界骨架
  人物和设备占据空间位置
  空间关系影响动作选择、传播结果和任务可行性
  时间演化发生在空间结构之上
```

### 3.4 2D/3D 在创新中的位置

```text
共享世界真相
  ├─ 2D：高吞吐执行和批量评测
  └─ 3D：结构、位置、轨迹与可达性校准
```

双表示本身不自动构成创新。论文必须证明 3D 校准对 benchmark 有实际作用，例如发现不合理设备位置、不可达路径、错误邻接或 2D 空间投影错误。

如果 3D 最终只提供截图，审稿人很容易将其视为展示功能。因此投稿主张应写成“空间一致性与校准机制”，不要写成“我们实现了 3D viewer”。

### 3.5 必须提供的实验

```text
实验 A：空间表示消融
  无空间结构
  仅房间 ID
  房间邻接图
  完整空间投影

观察
  空间 grounding 成功率
  指代消歧准确率
  跨房间任务成功率
  上下文 token 成本

实验 B：空间因果任务
  改变房间邻接但保持设备集合相同
  改变人物位置但保持语言指令相同
  改变设备位置但保持设备类型相同

观察
  Agent 是否随空间条件改变动作
  是否仍然机械复用原计划

实验 C：双表示一致性
  房间拓扑一致
  设备位置一致
  人物轨迹一致
  任务事件一致
```

实验 B 尤其重要。它能证明模型使用了空间关系，而非从设备名或文本模板中猜答案。

### 3.6 审稿风险

```text
风险一
  “这只是给 SimuHome 加了地图”

回应证据
  新的空间因果任务
  新的空间消融
  空间条件改变导致任务可行性和最优动作变化

风险二
  “3D 只是可视化”

回应证据
  3D 校准发现并修正 2D 场景错误
  自动空间一致性指标

风险三
  “给模型更多空间信息自然会更好”

回应证据
  同时报告准确率、token 成本和信息泄漏
  比较紧凑拓扑与完整几何
```

## 4. 核心创新二：面向长期共居的闭环主动服务评测

### 4.1 建议投稿表述

> 我们提出一种长期闭环主动服务 benchmark，将住户活动、环境变化、历史交互和 Agent 服务置于连续生活时间线上，使主动服务的触发时机、个性化适配、累积收益、错误干预和用户打扰能够被统一评测。

这项创新的关键推进是：

```text
从一次性推荐
  推进到持续观察后的服务决策

从静态家庭上下文
  推进到会被行动改变的动态生活过程

从单次成功率
  推进到累积收益与干扰成本

从独立 episode
  推进到跨事件、跨任务、跨时间段的连续评测
```

### 4.2 为什么 PersonalHomeBench 之后仍有空间

PersonalHomeBench 已经包含主动推荐与计划生成，所以我们的创新必须落在“长期闭环”上。

```text
上下文式主动任务
  给定家庭资料和当前情境
  生成推荐或计划
  任务在输出后基本结束

长期闭环主动服务
  Agent 连续观察生活事件
  从重复行为中形成或修正认识
  判断现在是否需要服务
  服务会改变设备、环境和人物状态
  后续反馈继续进入 Agent 历史
  多次决策共同决定最终评价
```

这使研究问题从“推荐得好不好”推进到：

```text
什么时候应该服务
什么时候应该保持沉默
对谁采用什么策略
一次服务的长期后果是什么
新证据出现后是否会修正旧偏好
```

### 4.3 评测对象

长期层应当测量五种能力：

| 能力     | 评测问题                               |
| -------- | -------------------------------------- |
| 偏好形成 | 能否从多次行为中提取稳定偏好           |
| 偏好修正 | 新证据出现后能否更新过期认识           |
| 服务时机 | 能否在正确时刻行动，并在证据不足时等待 |
| 成员区分 | 能否避免把一个人的偏好应用到另一人     |
| 长期协调 | 能否处理跨时间任务和并发生活事件       |

### 4.4 任务示例

```text
示例一：睡眠温度偏好
  第一天：用户手动把卧室从 24°C 调到 22°C
  第二天：再次出现相同行为
  第三天：用户提前回房，但同时感冒

评测
  Agent 是否学到一般偏好
  是否结合当天异常条件调整
  是否过早干预

示例二：老人夜间活动
  多日出现夜间起身、经过走廊、进入卫生间
  光照需求和家庭成员睡眠干扰同时存在

评测
  Agent 是否选择低亮度路径照明
  是否只在检测到相关人物时触发
  是否避免影响其他房间

示例三：空气质量主动服务
  做饭、开窗、人物离开和空气质量变化连续发生

评测
  Agent 是否选择合适设备与时机
  是否在自然通风已经足够时避免多余动作
  是否考虑能耗和噪声
```

### 4.5 指标创新

长期主动服务不能只使用任务成功率。建议定义累积服务效用：

```text
Proactive Service Utility
  = 服务带来的目标改善
  + 个性化匹配收益
  + 提前干预收益
  - 错误主动成本
  - 用户打扰成本
  - 无关设备副作用
  - 能耗或资源成本
```

需要同时报告：

| 指标                | 含义                           |
| ------------------- | ------------------------------ |
| Service Precision   | 主动服务中真正有益的比例       |
| Service Recall      | 应当服务的机会中实际覆盖的比例 |
| Timing Error        | 服务时刻相对合理窗口的偏差     |
| Disturbance Rate    | 打扰用户或影响无关成员的比例   |
| Preference Accuracy | 人物、条件和偏好匹配准确率     |
| Adaptation Speed    | 形成或修正稳定偏好需要多少证据 |
| Cumulative Utility  | 整段生活过程中的总收益         |

这些指标能够避免“越主动分数越高”的错误激励。

### 4.6 必须提供的实验

```text
实验 A：记忆范围消融
  无历史
  最近窗口
  结构化长期记忆

实验 B：生活时间消融
  独立 episode
  连续事件但无跨日状态
  完整长期生活过程

实验 C：主动策略消融
  永不主动
  规则触发
  LLM 主动服务
  记忆增强 LLM

实验 D：人物驱动源对照
  固定脚本
  带随机种子的规则生活流
  LLM persona
```

固定脚本和规则生活流是必要基线。若只使用 LLM persona，实验波动会让长期能力难以归因。

### 4.7 审稿风险

```text
风险一
  “PersonalHomeBench 已经做了 proactive”

回应证据
  强调连续时间、闭环反馈、跨日状态和累积指标
  对比一次性推荐与长期服务结果

风险二
  “长期任务只是很多短任务串起来”

回应证据
  设计必须依赖跨事件历史才能完成的任务
  加入偏好修正、跨成员污染和延迟后果

风险三
  “主动服务的好坏太主观”

回应证据
  明确服务窗口、目标状态、干扰事件和资源成本
  将主观评价限制为补充指标
```

## 5. 条件性贡献三：虚拟环境到现实平台的语义迁移与成对评测

### 5.1 建议投稿表述

在完成迁移实验的前提下，可以写成：

> 我们定义跨虚拟家庭世界与 Home Assistant 平台的统一 agent-facing 语义，并构建成对任务与契约测试，量化 Agent 策略在更换后端后的适配成本和性能保持程度。

这里有三个层级，投稿时必须区分：

```text
层级一：协议适配
  MCP tool 转 function schema
  REST / WebSocket 调用
  不构成研究创新

层级二：统一接口
  两个后端提供同名、同结构工具
  属于系统设计贡献

层级三：迁移评测
  同一任务在虚拟和现实后端成对出现
  同一 Agent 策略跨后端运行
  量化零样本或少量适配后的性能变化
  才具备较强投稿价值
```

### 5.2 第 1-6 篇文档带来的关键判断

第 1-2 篇证明 HA MCP 与 LLM function calling 能够跑通；第 3-5 篇证明外部研究接口可以基于 HA 官方 API 构建；第 6 篇最终锁定工具边界：

```text
接口层可以提供
  环境观察
  对象定位
  明确动作执行
  结果验证

接口层不能提供
  自动任务分解
  自动调度求解
  自动依赖消解
  自动隐含意图解释
```

这条边界本身很重要，但它更像 benchmark 有效性的设计原则。要成为创新，仍需跨后端实验。

### 5.3 真正需要研究的迁移问题

```text
语义覆盖
  虚拟环境中的观察、动作和状态
  有多少能够映射到 HA

行为保持
  同一策略切换后端后
  成功率、错误率和工具轨迹变化多少

适配成本
  是否需要改 prompt
  是否需要改工具选择逻辑
  是否需要专门微调

现实差异
  HA 的 area / entity / service 语义
  与虚拟空间拓扑和设备状态机有哪些不可消除差异
```

### 5.4 必须提供的实验

```text
成对任务集
  同一自然语言目标
  同一设备能力语义
  虚拟 backend 一份
  HA backend 一份

迁移设置
  Zero-adaptation
    只切换后端，不改 prompt 和策略

  Schema-only adaptation
    只提供后端 schema 差异

  Few-shot adaptation
    提供少量 HA 示例轨迹

观察
  任务成功率保持程度
  非法动作率
  工具调用数量变化
  prompt / adapter 修改量
  无法映射的语义比例
```

### 5.5 什么时候应当降级

出现以下情况时，第三项应放到 system feature 或 future work：

```text
只有 HA MCP demo
只有接口名称对齐
只有一个开灯或关电视案例
虚拟与 HA 使用不同任务
迁移时重新编写了整套 prompt
没有量化性能保持和适配成本
```

## 6. 三项贡献之间的关系

三项贡献需要形成一条递进链，不能写成三个独立项目。

```text
创新一：连续家庭世界
  提供空间、时间、人物、设备和环境的共同载体
            ↓
创新二：长期闭环主动服务
  在该世界中定义新的长期任务与累积评价
            ↓
贡献三：虚实迁移
  检查前两项中形成的 Agent 能力能否跨后端保持
```

论文可以用一个统一问题贯穿：

> 智能家居 Agent 能否在连续家庭生活中理解空间、积累认识、适时服务，并将这种能力迁移到现实平台？

这个问题比“我们做了 2D、3D、MCP、HA 和长期记忆”更集中，也更容易组织实验。

## 7. 哪些内容不要写成创新点

以下内容可以进入系统实现或附录，投稿摘要和贡献列表不要单独列出：

| 内容                                | 正确定位                       |
| ----------------------------------- | ------------------------------ |
| Python MCP demo                     | 可行性验证                     |
| MCP tool 到 function schema 的转换  | 协议适配                       |
| `myserver`                        | 统一接口的实现载体             |
| REST / WebSocket 支持               | 平台接入方式                   |
| 五个或六个工具                      | 接口设计细节                   |
| TimeControlKernel                   | 连续世界和可复现实验的基础设施 |
| `api_queue` / `scheduler_queue` | 时间语义实现机制               |
| 设备 JSON schema                    | 声明式建模手段                 |
| 温度曲线                            | 环境动力学验证                 |
| 2D viewer                           | 执行与观察入口                 |
| 3D viewer                           | 空间校准载体                   |
| 接入 Home Assistant                 | 迁移实验前提                   |
| 支持更多设备                        | Benchmark 覆盖度               |

一个简单判断标准是：

```text
去掉某项技术名称后，
是否仍然存在一个新的研究问题、评测协议或可检验结论？

存在
  可以继续讨论为创新

不存在
  更可能是工程实现
```

## 8. 投稿贡献的强弱排序

### 8.1 当前建议

| 排名 | 投稿主张                     | 当前潜力 | 成立条件                                      |
| ---- | ---------------------------- | -------- | --------------------------------------------- |
| 1    | 长期闭环主动服务评测         | 高       | 任务必须跨事件依赖，指标覆盖收益与干扰        |
| 2    | 空间—时间一致的连续家庭世界 | 中高     | 空间必须产生新任务和因果消融，3D 必须承担校准 |
| 3    | 虚实语义迁移评测             | 中       | 必须有成对任务和量化迁移结果                  |

长期主动服务的潜在新颖性最高，因为它能够明确超越静态任务、一次性计划和短期记忆。空间化环境是它成立的世界基础，也可以形成独立实验。虚实迁移具有价值，但最容易退化成工程 demo。

### 8.2 最稳妥的贡献列表写法

```text
Contribution 1
  A continuous, spatially grounded household world benchmark
  that unifies topology, dynamics, human activities, and task events.

Contribution 2
  A long-horizon closed-loop protocol for evaluating personalized
  proactive service with cumulative utility and disturbance costs.

Contribution 3
  A paired virtual-to-HA evaluation showing how agent policies
  transfer under a shared interaction semantics.
```

如果第三项实验不足，贡献列表改成：

```text
Contribution 1
  连续空间家庭世界

Contribution 2
  长期闭环主动服务 benchmark 与新指标

System Capability
  HA 兼容接口与代表性现实部署案例
```

## 9. 创新点到证据的对应关系

| 创新主张               | 最关键证据                           | 缺少该证据时会怎样   |
| ---------------------- | ------------------------------------ | -------------------- |
| 空间—时间一致家庭世界 | 空间因果任务、空间消融、双表示一致性 | 退化为带地图的模拟器 |
| 长期闭环主动服务       | 跨事件任务、累积效用、主动与干扰对照 | 退化为多个短任务拼接 |
| 虚实语义迁移           | 成对任务、跨后端性能保持、适配成本   | 退化为 HA 接口 demo  |

可以进一步画成论文实验链：

```text
E1 环境有效性
  证明世界状态、空间关系和时间过程可信

E2 空间能力实验
  证明空间世界产生了已有任务体系外的新难度

E3 长期主动服务实验
  证明连续历史和闭环反馈改变模型表现

E4 消融与错误分析
  证明提升来自目标机制，而非更多上下文或工具泄漏

E5 虚实迁移实验
  证明策略能够跨 backend 保持
```

## 10. Benchmark 任务应围绕创新组织

任务分类不要继续照搬 HomeBench、SimuHome 或 SMH-Bench 的现有类别。新的任务轴应直接对应论文创新。

### 10.1 空间—时间任务轴

```text
S1 空间实体定位
  人物、设备、房间和相对位置

S2 空间指代与历史轨迹
  刚才的位置、离开/进入、相邻空间

S3 空间传播与副作用
  温度、光照、噪声或空气影响跨空间传播

S4 空间约束下的时间任务
  人物到达、离开、设备完成、环境阈值共同触发
```

### 10.2 长期主动服务任务轴

```text
L1 偏好发现
  从重复行为中形成假设

L2 偏好确认与修正
  新证据支持、反驳或限定旧认识

L3 主动时机
  立即服务、延迟服务、询问或保持沉默

L4 跨成员差异
  防止偏好和记忆错误迁移

L5 长期多目标协调
  舒适、能耗、噪声、安全和干扰共同存在
```

### 10.3 虚实迁移任务轴

```text
T1 状态查询迁移
T2 原子动作迁移
T3 多设备动作迁移
T4 事件等待与验证迁移
T5 空间语义缺口与降级处理
```

## 11. 第一篇论文的范围

### 11.1 必须交付的研究内容

```text
一套连续家庭世界定义
  空间关系、连续状态、人物事件和任务事件能够共同演化

一组空间因果任务
  改变空间条件会改变正确行为

一组有限但真实的长期任务
  必须依赖跨事件历史才能完成

一套主动服务指标
  同时测量收益、时机、错误主动和干扰

一组强基线与消融
  静态任务、短历史、规则主动、LLM 主动等
```

### 11.2 可以作为增强项

```text
完整 3D 校准工具
更多家庭和人物画像
更长时间跨度
多模态人物事件
Home Assistant 成对迁移实验
```

### 11.3 暂时不要扩大

```text
所有设备类型
高保真建筑物理
大规模 RL
复杂多智能体社会模拟
生产级 HA 平台改造
大量与创新无关的页面功能
```

范围控制的判断方式为：

```text
能直接加强空间因果、长期闭环或迁移证据
  进入论文范围

只能增加系统功能数量
  暂缓
```

## 12. 推荐论文叙事

### 12.1 一句话版本

> We introduce a continuous household world benchmark for evaluating whether smart-home agents can understand spatially grounded daily life, provide personalized proactive services over long horizons, and transfer their behavior from simulation to real-world home platforms.

### 12.2 中文版本

> 我们提出连续家庭世界 benchmark，用于评测智能家居 Agent 能否在具有空间结构和持续时间的家庭生活中积累个性化认识、作出低干扰的主动服务，并将形成的交互策略迁移到现实智能家居平台。

### 12.3 摘要论证顺序

```text
第一段：现有评测的分裂
  控制、时间、个性化、环境接地分别被推进
  持续家庭生活仍未成为统一评测单位

第二段：我们提出什么
  连续空间家庭世界
  长期闭环主动服务协议
  可选的虚实成对迁移评测

第三段：怎样验证
  空间因果任务
  长期主动服务任务
  累积效用与干扰指标
  消融和跨后端实验

第四段：得到什么结论
  哪些模型在连续生活中明显退化
  空间、记忆和反馈分别带来什么影响
  虚实迁移损失来自哪里
```

### 12.4 可考虑的标题方向

```text
SimuHome-Live:
A Continuous Household World Benchmark for Long-Horizon Proactive Agents

LivingHomeBench:
Evaluating Spatially Grounded and Proactive Agents in Continuous Home Life

HomeWorld:
From Episodic Smart-Home Tasks to Long-Horizon Interactive Living
```

标题暂时突出 `continuous household world` 和 `long-horizon proactive agents`。MCP、Home Assistant、2D/3D 和时间核不进入标题。

## 13. 投稿前仍需完成的新颖性核查

当前判断主要相对于 HomeBench、SimuHome、PersonalHomeBench 和 SMH-Bench。正式投稿前还需要扩大检索范围，重点排查：

```text
Embodied AI 中的长期家庭环境

带干扰成本的主动服务指标
```

尤其需要核查两个风险：

```text

“主动服务效用 - 干扰成本”是否已有成熟评价协议
```

```text
To the best of our knowledge
Among existing smart-home agent benchmarks
```

## 14. 最终收束

当前项目的投稿价值不取决于实现了多少接口、设备或页面。真正需要守住的是一条研究主线：

```text
现有智能家居 benchmark
  主要以独立任务评测能力
            ↓
我们提出连续家庭世界
  空间、时间、人物、环境和任务共同演化
            ↓
在其中评测长期闭环主动服务
  学习偏好、选择时机、控制干扰、修正认识
            ↓
进一步检查策略能否迁移到现实平台
```

投稿时最稳妥的贡献结构为：

```text
两项核心创新
  1. 空间—时间一致的连续家庭世界 Benchmark
  2. 面向长期共居的闭环主动服务评测与累积指标

一项条件性贡献
  3. 虚拟环境到 Home Assistant 的成对语义迁移评测

基础设施
  时间核、任务事件、MCP、myserver、HA adapter、2D/3D viewer
```

如果第三项没有形成量化迁移实验，就把它放在系统能力中。前两项必须各自拥有新的任务、指标、对照和消融，才能真正构成论文创新。

# 03：沙盒全链路部署（SimuHome → MQTT → HA）

目标：复刻 3 房间 / 25 实体的模拟家庭，让 MCP 在可控沙盒里跑。
以下命令在 Windows PowerShell 实测通过；Linux / macOS 用每步给出的等价命令。

## 0 数据流

```text
SimuHome :8000 ◄────► 发布器（宿主机 Python）────► MQTT broker :1883
   ▲                     轮询 /api/home/state，发 discovery 与状态     │
   │                                                                  ▼
   └──── 命令主题 ◄──── HA 的 MQTT 集成（host.docker.internal:1883）:8123
                        设备以 MQTT discovery 自动进入 HA（25 个实体）
```

## 1 克隆并启动 SimuHome

```powershell
cd <repo>
git clone https://github.com/Mr-luo-q/Simuhome_experiment.git simuprocject\Simuhome_experiment
cd simuprocject\Simuhome_experiment
uv sync          # 或 python -m pip install -e .
```

```text
说明  我们实测的 commit 是 f8a813f；home_full.json 就在这个仓库根目录。
      论文官方仓库 holi-lab/SimuHome 不含 home_full.json，本链路以 Mr-luo-q 仓库为准。
      只跑仿真与控制链路不需要模型 key；跑上游评测才要（按上游 README 配 .env）。
      一键脚本用的是 PATH 里的 python；用 uv 的话先激活 .venv，或改用下面的 uv run 命令。
```

启动 API（一键脚本会自动做；手工方式如下）：

```powershell
cd simuprocject\Simuhome_experiment
uv run python -m src.simulator.api.app     # 监听 8000（或激活 .venv 后 python -m src.simulator.api.app）
# 上游自己的入口等价：uv run simuhome server-start
# 健康检查：http://127.0.0.1:8000/api/__health__
```

SimuHome 重启后 home 是空的（房间数 0、设备接口 404、写入会 verified=false），需要载入 home：

```powershell
curl.exe -X POST http://127.0.0.1:8000/api/simulation/reset `
  -H "Content-Type: application/json" --data-binary "@home_full.json"
```

## 2 起 HA 容器

```powershell
$env:HA_CONFIG_DIR = "D:\homeassistant\config"    # 换成你想放 HA 配置的目录
docker compose -f deploy\compose.yaml up -d
```

浏览器打开 http://127.0.0.1:8123 完成初始化，然后创建长期令牌（用户名 → 安全 → 长期访问令牌），
存成单行文件：`_secrets\ha_token.txt`。

## 3 装 Mosquitto 并生成账号

```text
安装   Windows：从 mosquitto.org 下载安装（本机 _tools\mqtt\ 留存的安装包不入库）
       Linux：apt install mosquitto；macOS：brew install mosquitto
```

```powershell
# 生成账号密码（写入 broker\mosquitto.passwd 与 broker\mosquitto.credentials.txt）
powershell -NoProfile -ExecutionPolicy Bypass -File simuhome_mqtt_publisher\broker\make_credentials.ps1
# 启动 broker（自动把工作目录设为 broker 目录，相对路径配置才成立；内含健康检查）
powershell -NoProfile -ExecutionPolicy Bypass -File simuhome_mqtt_publisher\broker\start_mosquitto.ps1
```

Linux / macOS 等价命令：

```bash
cd simuhome_mqtt_publisher/broker
mosquitto_passwd -c -b mosquitto.passwd simuhome '<你的口令>'
printf 'simuhome\n<你的口令>\n' > mosquitto.credentials.txt
mosquitto -c mosquitto.conf        # 需要在 broker 目录下运行（相对路径）
```

## 4 在 HA 里添加 MQTT 集成

```text
设置 → 设备与服务 → 添加集成 → 搜 MQTT → 填写：
  Broker    host.docker.internal      （Windows Docker Desktop；Linux 见 05 文档）
  Port      1883
  Username  与 make_credentials 输出一致（默认 simuhome）
  Password  同上
  协议      MQTT v5（本机实测 protocol=5）
```

提交后显示连接成功。此时还没有设备——设备由下一步的发布器自动发现。

## 5 启动发布器

```powershell
cd simuhome_mqtt_publisher
python -m pip install -r requirements.txt
powershell -NoProfile -ExecutionPolicy Bypass -File publisher\start_publisher.ps1
```

发布器会发 retained discovery，HA 自动建实体；约 10 秒后在 HA 能看到 `switch.simuhome_*` 等。
可选：把自动生成的实体 id 改成规范名（幂等，可重复跑）：

```powershell
python publisher\rename_entities.py --token-file ..\_secrets\ha_token.txt
```

## 6 日常一键拉起

```powershell
$env:HA_CONFIG_DIR = "D:\homeassistant\config"    # 首次建 HA 容器用；容器已存在可忽略
powershell -NoProfile -ExecutionPolicy Bypass -File _tools\start_simuhome_stack.ps1
# 需要把仿真重置回初始状态时加 -ResetHome
```

脚本是幂等的：已经跑着的服务会跳过；末尾汇总应显示：

```text
SimuHome 房间数   3（应为 3）
HA 实体           25 个（应为 25），其中 unavailable 0 个
```

## 7 验证 MCP 侧

```powershell
cd ha_mcp_universal
copy config.example.yaml config.yaml       # 首次
$env:HA_TOKEN = (Get-Content ..\_secrets\ha_token.txt -Raw).Trim()
python tests\test_e2e_real_ha.py --config config.yaml    # 22 / 22
```

## 8 停止与重置

```powershell
# 停发布器 / 停 broker（HA 与 SimuHome 用各自方式停）
powershell -File simuhome_mqtt_publisher\publisher\stop_publisher.ps1
powershell -File simuhome_mqtt_publisher\broker\stop_mosquitto.ps1

# 重置仿真到 home_full.json 初始状态
powershell -File _tools\start_simuhome_stack.ps1 -ResetHome
```

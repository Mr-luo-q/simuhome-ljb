# 04：米家真机接入

目标：把米家设备接进 HA，再让 MCP 认领它们。这一层不依赖沙盒，可以独立做。
集成本体是小米官方开源项目，不在本仓库里；本仓库负责的是"认领规则 + 统一语义"。

## 1 装集成（HACS 路线）

```text
① 如果你的 HA 还没有 HACS：按 HACS 官方文档安装（本机 custom_components 下已有 hacs）
② HACS → 集成 → 右上角菜单 → 自定义仓库：
     仓库地址  XiaoMi/ha_xiaomi_home
     类别      集成
③ 搜索 "Xiaomi Home" 安装，重启 HA
```

不想用 HACS 时，也可以按上游仓库 README 手工把 `custom_components/xiaomi_home`
拷进 HA 配置目录并重启。

## 2 登录米家并导入设备

```text
设置 → 设备与服务 → 添加集成 → 搜 "Xiaomi Home" → 登录米家账号
（本机实测：中国大陆区）
登录后选择要导入的设备；HA 会为每台设备建实体，平台标记为 xiaomi_home
```

## 3 MCP 侧认领

`ha_mcp_universal\config.example.yaml` 已内置米家认领段，复制成 config.yaml 后即可用：

```yaml
claim:
  - name: xiaomi                # 米家：只写规则，不写专有代码
    platforms: [xiaomi_home]
    domains: [switch, light, climate, fan, cover, number, select, sensor]
    id_source: device_name
    exclude_category: [config, diagnostic]
    exclude_entities: ["button.*", "update.*", "*_reset_*"]
```

```text
id_source: device_name   用设备名生成 device_id；首次扫描写 data\device_aliases.yaml
aliases.file             生成后可手工编辑成好读的 id（中文设备名自动生成不了有意义的 id）
exclude_*                排除配置/诊断类实体，避免噪声进入工具面
```

## 4 验证

```powershell
cd ha_mcp_universal
$env:HA_TOKEN = "<你的令牌>"
python -m home_mcp.entry --config config.yaml --dry-run      # 装配检查
# 起来后让模型或手工调用：
#   inspect_device  {"device_id": "<别名文件里的 id>"}
#   execute_action  {"device_id": "...", "action": "set_temperature", "params": {"value": 4}}
```

本机实测：米家冰箱在 HA 里拆成两个设备（`cn_911432173_cold` / `cn_911432173_freeze`），
`set_temperature` 可把冷藏从 2 度切到 6 度（见 `ha_mcp_universal\tests\test_llm_fridge.py`，
DeepSeek 直连 MCP 实测 6/6）。

## 5 注意

```text
云设备写入慢       米家云端偶尔 >10 s，config 里 ha.timeout_s 默认 25、
                  execution.verify_delay_ms / verify_attempts 已按云设备放宽
verified=false    命令被 HA 收下但窗口内没确认落地；别当成功，也别算调用失败
掉线              execute_action 返回 DEVICE_UNAVAILABLE，六字段为 null（不是 false）
登录失败          换网络/关代理重试；地区选错、验证码风控都可能失败（与 MCP 无关）
```

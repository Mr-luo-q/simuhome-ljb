## 2. 设备建模机制分析文档

在推进代码之前，先写了[设备建模机制分析_从SimuHome与SMHBench到我们的方案选择.md](../related%20paper/设备建模机制分析_从SimuHome与SMHBench到我们的方案选择.md)，分三部分：

1. **SimuHome 的 Matter 依赖建模** — Matter 承担双重角色：向真实设备迁移的协议标准 + 操作依赖链的执行框架。三层约束（设备级 Power Dependency → Cluster 内跨属性约束 → tick 时序约束）。结论：我们不需要 Matter 协议本身（统一 MCP 语义已解决迁移），但需要操作依赖链执行机制。

2. **SMH-Bench 的声明式 schema + 校验网关** — HomeEnv 的 5 阶段校验管线（设备存在 → 操作存在 → 参数结构 → 参数约束 → 执行）。关键缺口：不检查跨操作依赖。

3. **我们的方案选择** — 推荐混合方案（方案 D）：声明式约束层 + 统一校验网关 + 设备状态机执行层。

## 3. 首版设备建模：空调、风扇、取暖器

落地文件：[首版设备建模_空调风扇取暖器.md](../sandbox/firstdemo/首版设备建模_空调风扇取暖器.md)

三设备统一 `is_on` 开关，无电源类型区分：

| | 空调 | 风扇 | 取暖器 |
|---|---|---|---|
| 功能 | 制冷+制热+送风 | 仅送风 | 仅制热 |
| 操作数 | 5 | 3 | 3 |
| 核心约束 | 调温需开机+制冷/制热模式 | 调速需开机 | 调温需开机 |
| 温度效应 | 制冷/制热 0.3°C/tick | 影响空调速率系数 | 制热 0.25°C/tick |

环境效应实现为 `min(1.0, Δt/3)` 因子限制，防止极端温差下单 tick 跳变过大。

## 5. 关键工程问题及解决

### 5.1 Python 数字前缀文件名

文件名 `6_world_state.py` 等以数字开头，Python 无法 `import`。解决方案：所有跨文件引用通过 `_import_neighbor()` 手动加载，使用 Python 合法别名并在 `exec_module` 前注册到 `sys.modules`，避免 dataclass 内部查找失败。

### 5.2 Reset 深拷贝 Bug

`_init_world()` 中 `DeviceState` 对象被引用共享（而非拷贝），导致运行时修改状态后 reset 拿到的是被改过的对象。修复：`copy.deepcopy(dev_info["init_state"])`。

### 5.3 DeepSeek V4 Flash 思考模式

DeepSeek 默认开启 thinking mode，`reasoning_content` 字段在 function calling 消息历史中导致 API 400 错误。修复：请求中加入 `extra_body={"thinking": {"type": "disabled"}}`。

### 5.4 浏览器交互看不到过程

SSE 推送在浏览器端不够稳定。解决方案：改为轮询模式（500ms）+ SSE 作为补充。按钮操作后立即 `fetch` 刷新状态。每步之间加 1.5 秒延迟，让浏览器有时间渲染交互事件。

## 6. LLM 交互测试结果

`test/demo_interactive.py` 实现了 SimuHome ReAct 式循环：观察 → LLM 决策（function calling）→ 调沙箱 API → 推进时间 → 循环。

端到端验证通过的场景：

- **客厅制冷**：LLM 正确执行 `turn_on → set_mode(cool) → set_temp(20) → set_fan(high) → advance 30 ticks`，客厅 24°C → 21.3°C。邻接房间也有热传导降温。
- **卧室取暖**：在客厅已制冷的场景下，单独开启卧室取暖器到 28°C，40 tick 后卧室从 24°C → 26.95°C，客厅保持 21.4°C，温差 5°C+。邻接交换和自然回归均正常。
- **错误自适应**：LLM 用错误设备 ID（如 `living_room_ac_1`）查询时，从返回 error 中自动修正为正确 ID（`living_room_air_conditioner_2`）。

## 7. 接口体系

| 端点 | 方法 | 用途 |
|------|------|------|
| `/api/state` | GET | 全局状态（房间温度+设备状态） |
| `/api/actions/{device_id}` | GET | 设备操作列表+参数 schema |
| `/api/action` | POST | 执行设备操作 |
| `/api/step` | POST | 推进 1 tick |
| `/api/fast-forward/{n}` | POST | 快进 n ticks |
| `/api/reset` | POST | 重置 |
| `/api/event` | POST | LLM 交互事件推送（供浏览器显示） |
| `/api/stream` | GET | SSE（辅助通道） |

首版不使用 MCP 协议，直接 HTTP+JSON。MCP adapter 后续追加。

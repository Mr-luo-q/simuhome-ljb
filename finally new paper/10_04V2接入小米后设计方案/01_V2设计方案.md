## 1. 目标与判据

```text
目标        同一套 8 工具 / 8 动作 / 6 字段 / 12 错误码，零专有代码接入 HA 上任意集成设备
判据        控制语义的最大公约数：新设备先投影到现有语义；投影不了、且缺的维度
            跨 ≥3 类设备且 ≥2 个集成共有，才允许扩词表；否则写进 scoping 不接
不做什么    不为某个品牌写特例；不追求"接口一个字不改"；不接时间类、诊断类、复合属性
```

## 2. 对外契约（对模型可见，v2 保持不变）

### 2.1 八个工具

| 工具 | 参数 | 状态 | 主要错误码 |
| --- | --- | --- | --- |
| `observe_home` | 无 | 已实现 | HA_UNREACHABLE |
| `inspect_room` | room_id | 已实现 | HA_UNREACHABLE / UNKNOWN_ROOM |
| `inspect_device` | device_id | 已实现 | HA_UNREACHABLE / UNKNOWN_DEVICE |
| `execute_action` | device_id, action, params | 已实现 | UNKNOWN_DEVICE / DEVICE_UNAVAILABLE / UNSUPPORTED_ACTION / BAD_REQUEST / SERVICE_ERROR |
| `time_control` | op(advance/schedule/list/cancel), seconds, at, steps | 未实现 | NOT_IMPLEMENTED |
| `check_goal` | conditions[], keep[] | 已实现 | BAD_TARGET / BAD_REQUEST |
| `query_events` | since, until, entity_id, limit | 已实现 | HA_UNREACHABLE / BAD_REQUEST |
| `memory` | op, key, value（当前契约） | 未实现 | NOT_IMPLEMENTED |

### 2.2 八个动作

```text
turn_on / turn_off / toggle              开关、灯、风扇、空调
set_mode(mode)                           空调 hvac_mode、select 选项
set_temperature(value)                   空调设定温度、number 设定值（冰箱温区）
set_percentage(value)                    风扇档位、number 百分比
set_brightness(value)                    灯亮度（light.brightness_pct）
set_position(value)                      窗帘位置（cover.set_cover_position）
```

### 2.3 六个状态字段

```text
on        bool     是否通电/在运行        power 角色
mode      string   运行模式               mode 角色（climate 的 state / select 的选项）
target    number   目标值（温度等）        target 角色
level     number   档位百分比             level 角色（light 亮度 / fan 档位 / number）
position  number   位置百分比             position 角色（cover）
current   number   设备自测当前值          current 角色（climate 属性 / sensor 温度）
掉线：字段 = null（不是 false）
```

### 2.4 十二个错误码（errors.py）

```text
HA_UNREACHABLE / UNKNOWN_DEVICE / UNKNOWN_ROOM / DEVICE_UNAVAILABLE /
UNSUPPORTED_ACTION / SERVICE_ERROR / VERIFY_TIMEOUT / INVALID_TIME /
UNKNOWN_KEY / BAD_TARGET / BAD_REQUEST / NOT_IMPLEMENTED
```

### 2.5 统一返回外壳（server.py）

```json
{"ok": true, "data": {}, "error": null}    # meta（elapsed_ms / clock）只在服务端内部
```

## 5. 模块规格

### 5.1 registry/claim.py —— 认领层

```text
职责      把"哪些实体属于我们"从代码变成配置：一条规则命中即收
输入      entities / devices 注册表 + list[ClaimRule]
输出      ClaimResult{entities[ClaimedEntity], by_rule{规则名: 数量}}
规则字段  name / platforms / domains / entity_id_prefix / unique_id_prefix /
          id_source(identifier|device_name|entity_name) /
          exclude_category(默认 config+diagnostic) / exclude_entities(fnmatch) /
          kind_by_suffix{后缀: 类别}
类别判断  kind_of()：先匹配 unique_id 后缀表；没命中且域在
          CONTROLLABLE_DOMAINS（switch/light/climate/fan/cover/number/select）时用域
默认行为  不配 claim → default_rules()：platform=mqtt + unique_id 前缀 simuhome_
          + 后缀 _switch/_climate/_fan，即 v1 行为
不负责    不看状态、不管房间、不生成动作；只做"收不收 + 算什么类别"
对应文件  src\home_mcp\registry\claim.py（+ 同名 .md）
```

### 5.2 registry/aliases.py —— 设备别名

```text
职责      给认领到的 HA 设备一个可读、可手改的逻辑名
输入      认领到的设备列表（id / name / identifiers）
输出      data\device_aliases.yaml：
          devices: {HA 设备 id: 逻辑 id}；entities: 预留（当前未使用）
生成规则  中文名不硬拼英文 → 退回 identifiers；仍压不出 → dev_<sha1 前 6>；
          逻辑 id 冲突时追加 _2 / _3；已有条目一律不覆盖
读取时机  启动时 load_aliases；首启 ensure_aliases_file 写回
不负责    不做实体级别名、不做翻译；改完文件要重启 MCP 生效
对应文件  src\home_mcp\registry\aliases.py（+ .md）
```

### 5.3 registry/roles.py —— 角色推断与拆分

```text
职责      把"一台 HA 设备上的若干实体"投影成"一到多台逻辑设备"，每台只带六角色
角色      power / mode / target / level / position / current
          （字段映射：power→on，其余同名）
角色判断  switch/light/fan → power；climate → power+mode+target+current；
          light 有 brightness 再加 level；fan 有 percentage 再加 level；
          cover → position；select → mode；
          number：device_class=temperature 或单位 °C → target；
                   min/max 落在 0~100 → level；其余 None；
          sensor：device_class=temperature → current；其余进 extras
拆分规则  同一角色出现多条"带方位词"的记录（冷藏/冷冻/左/右/主/次/客厅/卧室…）→
          以方位词为组，每组一台逻辑设备 <base>_<qualifier>；
          没有方位词的多值条目降级 extras；共享角色（整机模式）挂第一台；
          只有 current 的设备不进设备清单（房间传感器组）
输出      ProjectedDevice{device_id, ha_device_id, area_id, name, kind, roles, extras}
不负责    不生成动作、不调服务、不算参数范围
对应文件  src\home_mcp\registry\roles.py（+ .md）
```

### 5.4 registry/actions.py —— 动作生成与执行方案

```text
职责      角色 → 动作清单（带参数范围）；动作 → 执行方案；动作 → 回读期望
生成规则  power  → turn_on / turn_off / toggle
          mode   → set_mode(enum 来自 options 或 hvac_modes)
          target → set_temperature(min/max/step 来自设备属性)
          level  → light: set_brightness(0~100)；fan: set_percentage(0~100, percentage_step)；
                   number: set_percentage(min/max/step)
          position → set_position(0~100)
服务映射  (动作, 域) → (HA 服务, 参数字段)：
            turn_on/off/toggle × switch/light/fan/climate → 同名服务
            set_mode × climate → set_hvac_mode(hvac_mode)
            set_mode × select → select_option(option)
            set_temperature × climate → set_temperature(temperature)
            set_temperature × number → set_value(value)
            set_percentage × fan → set_percentage(percentage)
            set_percentage × number → set_value(value)
            set_brightness × light → turn_on(brightness_pct)
            set_position × cover → set_cover_position(position)
回读期望  turn_on→(on,True)；turn_off→(on,False)；toggle→on 取反；
          set_mode→(mode,参数)；set_temperature→(target,参数)；
          set_percentage/set_brightness→(level,参数)；set_position→(position,参数)
不负责    不校验参数是否越界（校验在 execute_action）；不发服务调用
对应文件  src\home_mcp\registry\actions.py（+ .md）
```

### 5.5 backend_ha/mapping.py —— 注册表视图与查询

```text
职责      三张注册表 + 状态 → RegistryView；给工具提供房间/设备/环境量/写路径查询
数据结构  DeviceRow{device_id, entity_id(主实体), domain, kind, area_id,
                     ha_device_id, name, roles, extras}
          RegistryView{devices{逻辑id: DeviceRow}, sensors_by_area{房间: [实体]},
                       areas{房间: 显示名}, time_entity, claimed}
环境量    认领到的 sensor，且其所在设备没有可控实体（冰箱内部温度不进房间环境量）；
          collect_env 只取 device_class ∈ {temperature, humidity, illuminance, pm10}
区域      areas.alias 覆盖显示名；areas.hide_empty=true 时隐藏"没设备也没环境量"的区域
虚拟时间  仍按 v1 约定：unique_id == simuhome_virtual_time
写路径    summarize_device_row / device_actions_v2 / plan_row_execution：
          有 roles 走角色；没有 roles 的老式行回退 v1 逻辑
          resolve_target：<room>.<metric> 从 sensors_by_area 取；<device_id>.<字段>
          从设备六字段取；解析不了抛 KeyError → BAD_TARGET
不负责    不建网络连接、不调服务
对应文件  src\home_mcp\backend_ha\mapping.py（+ .md）
```

## 6. execute_action 的四道闸门与回读

```text
① 设备存在        view.devices 没有该 device_id            → UNKNOWN_DEVICE
② 实体可用        角色实体全部 unavailable/unknown          → DEVICE_UNAVAILABLE（命令不下发）
                   （多角色设备只要有一路活着就继续）
③ 动作支持        device_actions_v2 没有该动作              → UNSUPPORTED_ACTION
                   plan_row_execution 抛 KeyError 同码
④ 参数范围        本地按设备自报 min/max/enum/step 校验      → BAD_REQUEST（不发给 HA）

执行   POST /api/services/{domain}/{service}，负载 {字段: 值, entity_id}
       例：冰箱 set_temperature → number.set_value(value=5)
回读   config.execution.verify_delay_ms × verify_attempts（当前 800ms × 4）
       数值比较容差 = 参数步长 / 2；超过窗口没变 → verified=false + verify_note
       verified=false 不算调用失败（HA 服务调用是异步的，云设备落定可达数秒）
返回   {device_id, action, params, state_after, steps[], verified, elapsed_ms, verify_note?}
```

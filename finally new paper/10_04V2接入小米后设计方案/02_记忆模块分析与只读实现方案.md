## 2. 为什么只读（定稿理由）

```text
SMH-Bench 口径   记忆由题面给、模型只用不写；判分前提"不使用所提供的记忆就解不出来"
端侧小模型       无参数工具零决策；key 是自由字符串，最容易出现"写 bedtime、读 sleep_time"
                 （正好对应 SMH 点名的"参数名错"这类失败）
可复现性         记忆是实验变量，由实验方固定；写回会让同一题在不同轮次漂移
实现成本         读文件约等于零依赖；写回要 sqlite + 并发 + 覆盖/遗忘策略
论文口径         只读 = 测"会不会用"；"会不会记"如实写进 scoping
```

### 2.1 HA 自身有没有可改造的记忆接口（本机核实：没有合适的）

在本机 HA（2026.6.4）上实测 `/api/services`，可写的"存储类"域名只有这些：

```text
input_text     set_value                     单条文本；实体 state 上限 255 字符
text           set_value                     单条文本实体，同上
todo           add_item / get_items /        扁平字符串列表，没有层次、没有 key-value
               update_item / remove_item
input_select   set_options                   枚举/选项列表
input_number / counter / input_boolean       数值与布尔
persistent_notification / notify             UI 消息，不是存储
```

现有实体里也只有 `todo.shopping_list`（购物清单），没有别的可用存储实体。

```text
容量      input_text / text 是 255 字符上限；todo 是扁平条目；装不下 KB 级的偏好文本
结构      没有 key-value、没有嵌套；偏好/约束/日程混成一个列表，模型不好用
写入      HA 这些接口天然可写（set_value / add_item），会破坏"只读"的定稿口径
语义污染  记忆一旦放进 HA 就变成实体，会进状态表，需要额外过滤；
          也不符合"记忆是任务输入、不是设备"的定位
内部存储  /config/.storage、recorder DB 是 HA 内部实现，没有对外 API，
          直接读写既脆弱又危险
```

结论：记忆不落在 HA 里。按第 3 节直接读 `data\memory.yaml`，
文件在 HA 之外，天然只读、无容量与结构限制。
备选（不推荐）：如果以后要求"能在 HA UI 里编辑记忆"，可以用 `todo` 列表，
代价是扁平结构、可写、且记忆会以实体形式污染 HA 状态。

## 3. 只读语义规格

### 3.1 工具契约（读写同构，本期只实现读）

```text
名字    memory
参数    op    可选，枚举 read | write，默认 read
        text  可选；op=write 时必填（写入内容，本期未实现）
返回    read  → data = {text: <记忆文件原文>}；文件缺失时 text = ""
        write → 本期返回 NOT_IMPLEMENTED（参数形状已预留）
错误    op 非法 → BAD_REQUEST；op=read 却带 text → BAD_REQUEST（严格校验）
备注    整段读写模型：不做 key；写入语义是"整段替换"，后续实现
```

参数形态的取舍（待拍板 D1）：A 整段（op + text，推荐）；B 键值（op + key + value）。

### 3.2 文件与路径

```text
文件      config.memory.file（默认 ./data/memory.yaml）
解析      相对 config.yaml 所在目录（runtime.resolve_path，不按当前工作目录）
模板      ha_mcp_universal\memory.example.yaml（仓库内示例，复制到 data\ 后按实验改写）
格式      YAML 或任意文本；工具不解析、原样返回，不存在解析错误这一类失败
编码      UTF-8（无 BOM）；解码失败 → BAD_REQUEST，不静默替换字符
传输      走既有 JSON 外壳；server.py 已是 ensure_ascii=False
          （中文不转 \uXXXX：Qwen3-1.7B 实测 169 vs 547 token、
          小词表 218 vs 657，见 03 号 §2.4）
安全      记忆原文会进模型上下文，文件里不要放密钥或隐私数据
```

### 3.3 读取时机（二选一）

```text
A 启动读一次（与 13 号定稿一致，推荐）
  同一进程内稳定、可复现；缺点是改文件要重启 MCP 进程
B 每次调用读一次
  改完立即生效；缺点是一次实验内可能漂移，且每次多一次文件 I/O
建议：先按 A 实现；以后需要热更新再加配置开关 memory.reload: startup|always
```

### 3.4 错误与边界

```text
op 非法            → BAD_REQUEST（可选 read / write）
op=read 却带 text  → BAD_REQUEST（严格，避免模型误用）
op=write           → 本期 NOT_IMPLEMENTED（text 必填等校验等实现写时再加）
文件缺失           → {text: ""}，不报错（13 号验收口径）
文件不可读（权限）  → 待定，见 §7 D3
超大文件           建议实验方控制在 200 token 以内（≈300 中文字，Qwen 词表）；
                   读硬限 300 / 写硬限 200，见 03 号文档 §1.2
```

## 4. 实现清单（改动面）

```text

  memory：params 改成 op（read|write，默认 read）+ text（可选）；

  UNKNOWN_KEY 不再声明，errors.py 里的枚举保留（暂时用不到）
```

```text

```

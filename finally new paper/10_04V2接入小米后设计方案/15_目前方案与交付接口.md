# 15：目前方案与交付接口

写给人看的交接文档，读者：在 v2 上做强化学习 demo、数据合成或模型训练的人。本文只讲"现在有哪些接口、每个接口的语义、怎么对接、哪些不要依赖"，不讲内部实现；实现细节在各自的同名 `.md` 里。

核对日期 2026-10-07，对应代码 `ha_mcp_universal`（v2）。本文取代
`HomeAssistant双仓库接口分析\14_接口交接-八个工具与统一语义.md`（v1，冻结于 2026-09-23）。

## 0 先看清版本与当前工具面

```text
代码        ha_mcp_universal（v2）；ha_mcp_server 是 v1，已冻结
契约        contract\tools.py 里有 10 个 ToolSpec
当前开放    8 个（config.yaml 的 tools.expose 白名单控制；顺序 = tools/list 顺序）
            observe_home / inspect_room / inspect_device / execute_action / finish /
            inspect_time / time_control / memory
```

## 2 统一底座

### 2.1 动作调用 ACTION_CALL（立即执行与预约共用）

```text
ACTION_CALL = {device_id, action, params?}

execute_action 的输入       = ACTION_CALL
time_control.steps 的元素   = ACTION_CALL（逐字复用，不改名、不加字段）
到点执行与立即执行共用同一个执行内核 execution.perform_action
```

### 2.2 动作词表（8 个，按设备类别取子集）

```text
turn_on / turn_off / toggle
set_mode(mode)          空调模式、select 选项
set_temperature(value)  空调设定温度、number 设定值（冰箱温区）
set_percentage(value)   风扇档位、number 百分比
set_brightness(value)   灯亮度（预留，当前无实体）
set_position(value)     窗帘位置（预留，当前无实体）
```

参数范围优先取设备自报值；越界在本地拦下，不发 HA。

### 2.3 状态字段（6 个）

```text
on / mode / target / level / position / current
掉线（unavailable / unknown）时字段给 null，不是 false
```

### 2.4 错误码（12 个）与处理建议

```text
HA_UNREACHABLE      连不上 HA / 超时           环境故障：本步作废或重试
UNKNOWN_DEVICE      device_id 不存在           策略错误：负奖励
UNKNOWN_ROOM        room_id 不存在             策略错误
DEVICE_UNAVAILABLE  实体掉线                   环境故障：命令没下发，不算策略失败
UNSUPPORTED_ACTION  设备不支持该动作            策略错误：动作掩码没做好
SERVICE_ERROR       HA 拒绝服务调用             多为环境/参数问题
BAD_REQUEST         参数不合 schema / 越界      策略错误：本地已拦
BAD_TARGET          check_goal 目标写错         任务定义问题
INVALID_TIME        预约时间在过去 / 格式错      策略错误：要求绝对分钟时间
UNKNOWN_KEY         记忆键不存在                已废弃（memory 改成整段文本）
VERIFY_TIMEOUT      回读未按时变化              保留未用
NOT_IMPLEMENTED     工具未实现                  当前只剩 manage_rule 有代码概念
```

## 3 设备、时间与任务工具（6 个）

### 3.1 observe_home

```text
语义       "家里现在什么情况"：房间、每间环境量、设备清单、当前时间
输入       无
输出       rooms{<room_id>: {name, env{temperature, humidity, illuminance, pm10}, devices[]}}
           + time + clock + counts
错误       HA_UNREACHABLE
注意       输出形态还是字典；与数据合成端的 rooms 列表形态未对齐（留到最后统一收口）
```

### 3.2 inspect_room

```text
语义       一个房间的环境量 + 设备摘要 + 门状态
输入       room_id（如 living_room）
输出       {room_id, name, env{}, devices[
             {device_id, display_name, kind, device_type}], doors: null}
错误       HA_UNREACHABLE / UNKNOWN_ROOM / BAD_REQUEST
注意       doors 恒为 null（没有门磁实体）
           设备摘要已对齐数据合成端（2026-10-07）
```

### 3.3 inspect_device

```text
语义       一台设备的六字段状态 + 可用动作 + 参数范围
输入       device_id（如 living_room_ac、kitchen_fan、cn_911432173_cold）
输出       {device_id, entity_id, area_id, kind,
           state{六字段}, actions[{action, description, params{...}}]}
           actions 参数带 type / minimum / maximum / step / enum
错误       HA_UNREACHABLE / UNKNOWN_DEVICE / BAD_REQUEST
注意       掉线时 state 字段为 null，但 actions 照常返回（能力不随可用性变化）
```

### 3.4 execute_action

```text
语义       立即执行一次动作并回读；与预约到点共用执行内核
输入       ACTION_CALL：{device_id, action, params?}
输出       {device_id, action, params, state_after, state_diff, changed,
           steps[], verified, elapsed_ms, 可选 verify_note}
错误       UNKNOWN_DEVICE / DEVICE_UNAVAILABLE / UNSUPPORTED_ACTION /
           BAD_REQUEST / SERVICE_ERROR
四道闸门   设备存在 → 角色实体可用 → 动作支持 → 参数范围（全在本地先判）
verified   true = 窗口内确认状态到位；false = 命令收下了但没按时变化，不算调用失败
state_diff 只列实际变化的六字段，如 {"on": {"from": false, "to": true}}
```

### 3.5 finish

```text
语义       协议工具：声明本轮任务结束（完成或拒绝）；不碰 HA、不操作设备
输入       {outcome: completed|refused,
           reason_code?: OUT_OF_SAFE_RANGE|READ_ONLY_DEVICE,
           summary?: "一句话"}
输出       {accepted: true, outcome, reason_code, summary}
错误       BAD_REQUEST（outcome 非法 / refused 缺 reason_code /
           completed 带 reason_code / 多余字段）
RL 用法    终止动作；结束之后由 harness / check_goal 判分
```

### 3.6 inspect_time

```text
语义       读当前时间：家庭时区的分钟级时刻 + 时钟类型
输入       无（带参数 → BAD_REQUEST）
输出       {"now": "2026-10-08 09:30", "clock": "real|virtual"}
注意       与 time_control 共用同一个时钟（backend_ha\clock.py）；
           模型用它的 now 算 at，再调 time_control.schedule
```

## 4 记忆与判定工具（4 个；memory / time_control 开放，check_goal / query_events 保留隐藏）

### 4.1 memory

```text
语义       整段文本记忆：读原文 / 整段替换写入
输入       {op?: read|write，默认 read；text?: write 必填、read 禁止}
输出       read → {text}；write → {"code":"OK"}
规则       空文本拒绝（BAD_REQUEST）；写超 200 token 拒绝；
           读超 300 token 按内部策略截断；写入原子落盘 + 回读校验
错误       只用两个：BAD_REQUEST（参数/长度）、SERVICE_ERROR（文件读写/回读失败）
配置       memory.file / max_write_tokens / max_read_tokens
```

### 4.2 time_control

```text
语义       一次性预约：schedule 写单 / list 查未执行的单 / cancel 取消
输入       {op: schedule|list|cancel, at?, steps?, schedule_id?}
           at = "YYYY-MM-DD HH:MM"（家庭时区，分钟级）
           steps = 1~8 条 ACTION_CALL
输出       schedule → {schedule_id, at, status: pending}
           list     → {now, items:[{schedule_id, at}]}，只含还没执行的单
           cancel   → {schedule_id, status: cancelled}
可见性     list 只列没到执行时刻的单；已取消 / 已完成 / 失败的单内部留档，
           不再下发——取消之后 list 里立刻看不到（2026-10-09 修订）
时间       执行时刻落到整分 :00；验收窗口前后各 30 秒；
           过去 / 格式错 / 超 7 天 → INVALID_TIME
失败       T2：某步执行不了就记录该步，继续执行剩余步骤；
           到点设备掉线本期不专门处理
存储       data\schedules.db；调度器线程 + due 最小堆
```

### 4.3 check_goal

```text
语义       目标条件 + 无关状态保持两组判定
输入       conditions[{target, op, value}]，keep 同构可选
           target = <room>.<metric> 或 <device_id>.<六字段>
输出       goals + keep + all_pass
RL 用法    reward / 终止条件
```

### 4.4 query_events

```text
语义       查时间窗内的 logbook 事件
输入       since / until / entity_id / limit
输出       events[{ts, entity_id, state, name}] + counts
RL 用法    轨迹回放、调试、因果核对
```

## 6 已知边界与坑

```text
verified=false       命令发出去了但窗口内没确认落地；别当成成功，也别算调用失败
掉线                 实体 unavailable 时 execute_action 直接 DEVICE_UNAVAILABLE，
                     六字段为 null（不是 false）
参数越界             本地拦，不发给 HA（发给 HA 会 500）
时间                 只用绝对分钟级时间；没有相对时间、没有 advance、没有快进；
                     预约窗口是整分 ±30 秒
预约可见性           取消 / 已执行 / 失败的单从 list 消失（内部留档）；
                     模型永远只看到当前还有效的预约单
到点设备掉线         本期不专门处理，后续版本再定
observe_home 形态    仍是 rooms 字典；与数据合成端的列表形态还没统一（最后收口）
命名对齐              device_id / room_id 的 token 归一暂缓（模型从输出读取 id，
                     不阻塞当前对接）
episode 隔离          预约单写进 data\schedules.db；RL 实验要保证跨 episode 不互相污染
                     （当前启动清理策略未设计，实验前自行清库或换 db）
工具面                主配置开放 8 条；check_goal / query_events 保留隐藏，
                     要开就在 tools.expose 里加名字
```

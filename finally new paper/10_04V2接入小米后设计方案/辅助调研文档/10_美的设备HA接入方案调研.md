# 10：美的设备 Home Assistant 接入方案调研

2026-10-06 整理。核实范围：HA 官方集成文档、midea-local 依赖源码、HACS 社区项目 README、新闻报道。

## 1 结论

```text
美的有成熟 HA 方案，且同时存在三条技术路线：

  路线一  HA 官方集成 midea         本地直连，云端只取 token/key，35 类设备（HA 2026.8+）
  路线二  社区本地方案              midea_ac_lan 1,827★ / midea_smart_home 115★ /
                                   nbogojevic 486★（只做空调+除湿机）
  路线三  社区云方案                midea_auto_cloud 292★，44 类设备
  Matter  海外机型有认证（窗机、X23 烤箱），国内美居机型未以 Matter 为主推

对 v2 MCP 的意义：
  以上任一方案先让设备进入 HA，成为标准实体（climate / fan / switch / number / sensor），
  我们在 HA 实体层做语义归一；8 工具、8 动作、6 字段不需要任何美的专有代码。
  需要留意的只有一处：空调风速（fan_mode）目前不在八动作覆盖范围内，见 §6。
```

## 2 路线一：HA 官方核心集成 `midea`

职责：把使用美的协议的设备接进 HA，运行期完全局域网直连；云端只在配置阶段使用一次。

```text
首次配置（一次）                        运行期（长期）
  手机 App 账号                           HA ──局域网 TCP──> 美的设备
  美的美居 / MSmartHome / Midea Air /        （V1/V2/V3 协议，固定 IP 推荐）
  NetHome Plus（云端取自 midea-local）
        │ 取 V3 设备 token/key               状态：设备主动推送
        │ V1/V2 可完全跳过云端               控制：HA 本地直接下发
        v
  token/key 存入 HA 配置
```

支持设备 35 类，覆盖空调、除湿机、风扇、冰箱、洗衣机、干衣机、洗碗机、电/燃气热水器、空气净化器、加湿器、油烟机、微波炉、电饭煲、取暖器、马桶、集成吊顶灯等日常品类。

官方文档写明的限制（摘自 HA 集成文档 Troubleshooting）：

```text
协议  V1 / V2 / V3 设备可用；集成本身基于 API v1，部分新机型（API v2）只被部分支持
连接  V3 设备必须有正确 token/key；设备同一时间只接受一个本地连接，
      手机 App 或其他工具占用时配置会失败
网络  设备 IP 经 DHCP 变更后会显示 unavailable；建议静态 IP 或 DHCP 保留
```

本机现状（2026-10-06 实测）：

```text
容器 HA 版本        2026.6.4（ghcr.io/home-assistant/home-assistant:stable）
components/midea    不存在
python midealocal   未安装
结论                官方集成要求 ha_release 2026.8，本机升级容器后即可用；
                    当前 stable 已是 2026.9.x，HACS 已装（custom_components 下有 hacs）
```

逐 tag 探测的版本边界与文档一致：2026.7.4 及以前没有该组件，2026.8.0 起存在。配置流另有预置账号机制：先尝试官方维护的公共账号，失败再回落用户自填的美的账号（源码口径）。midea-local 云字典里国内账号对应美的美居（mp-prod.smartmidea.net），另有 MSmartHome / Midea Air / NetHome Plus / 东芝 IOLife 等条目。

## 3 路线二：HACS `midea_ac_lan`（本地，覆盖最广）

1,827★，HACS 默认库收录，要求 HA >= 2022.5（本机满足）。它是社区里最成熟的美的本地控制项目，与官方集成的底层库 `midea-local` 属于同源技术路线（双方 README 互相致谢）。

```text
支持品牌（README 列出 16 个）
  美的 / 华凌 / COLMO / 小天鹅 / 东芝 / 开利 / Comfee /
  Ariston / Beverly / Bugu / Electrolux / Netsu / ProBreeze /
  Rotenso / Vandelo / Wahin

支持设备 34 类：空调(AC)、除湿机(A1)、风扇(FA)、冰箱(CA)、
  洗衣机(DA/DB)、干衣机(DC)、洗碗机(E1)、电热水器(E2)、燃气热水器(E3)、
  取暖器(FB)、净化器(FC)、加湿器(FD)、油烟机(B6)、微波炉(B0)、
  电饭煲(EA)、净饮机(ED)、马桶(C2)、浴霸(26)、灯(13) 等
```

工作方式与官方集成一致：配置阶段登录美的账号取 token/key（可手动填写），之后完全局域网控制；状态靠设备长连接推送，另提供可调刷新间隔（默认 30 秒，0 表示不主动轮询）。

选择它的场景：官方集成尚未支持的机型、品牌（如东芝、开利），或者不想升级 HA 核心版本。

同一条本地路线上还有两个值得知道的实现：

```text
Cyborg2017/midea_smart_home   115★，HA >= 2025.12.4，36 个品类，中文文档 + QQ 群 +
                              AI 适配指南；首次配置从云端自动下载设备 Lua 协议脚本，
                              之后局域网控制（空调 0xAC、风扇 0xFA、除湿机 0xA1、
                              风扇灯 0x13、冰箱 0xCA、净化器 0xFC、取暖器 0xFB 等）
nbogojevic/...-lan            486★，只做空调 + 除湿机，V2/V3 本地控制；README 明确：
                              2021 年后部分美的机型实为涂鸦平台，美的协议系集成全部不适配，
                              且老型号名可能被新型号复用，光看型号名分辨不出来
```

## 4 路线三：HACS `midea_auto_cloud`（纯云端）

292★。登录 MSmartHome / 美的美居账号，通过美的云端 API 控制，自动下载设备对应的 Lua 协议文件；支持 44 类设备，覆盖面比本地方案更宽，映射文件可生成 sensor / binary_sensor / switch / select / climate / fan / water_heater 实体。

```text
优点   新机型（本地协议没适配、API v2）也能控制；不用管局域网发现
代价   依赖美的云，断网即失控；接口变更或账号风控会直接失效
衍生   Cyborg2017/midea_smart_home（115★，Lua 协议 + 本地控制，36 类设备，
       HA >= 2025.12.4），与路线一/二逻辑相同，仅作备选
```

## 6 接进 HA 之后，v2 MCP 怎么用

美的设备经上面任一方案接入后都是标准实体，映射关系如下：

```text
美的设备（HA 实体）      六字段                      可用动作
空调 climate            on / mode / target / current
                        turn_on / turn_off / set_mode / set_temperature
风扇 fan（或风扇灯）     on / level                  turn_on / turn_off / set_percentage
冰箱 number / switch     on / target                 turn_on / turn_off / set_temperature
除湿机 humidifier        on / mode / target          turn_on / turn_off / set_mode / set_temperature
空气净化器 fan           on / level                  turn_on / turn_off / set_percentage
洗衣机 / 洗碗机 switch   on                          turn_on / turn_off
```

对话例子（与冰箱 2→6°C 相同链路）：

```text
用户：把空调调到 26 度
模型：execute_action(device_id="livingroom.ac", action="set_temperature", params={"value": 26})
HA ：climate.set_temperature(temperature=26)
MCP：回读 climate 属性 target == 26 → verified=true
```

发现的缺口：空调风速档位在 HA 里通常暴露为 climate 的 `fan_mode` 属性（服务是 `climate.set_fan_mode`），部分集成才额外生成独立 fan 实体。当前八动作里 `set_mode` 只映射 climate 的 `hvac_mode` 与 select 的选项，`fan_mode` 没有对应动作。

```text
可选处理（等真机验证后再定）：
  A  把 fan_mode 当作 select 语义扩展进 set_mode（改动最小）
  B  新增第九动作 set_fan_mode（语义最清晰）
  C  若该集成同时暴露 fan 实体，直接走 set_percentage，不改（最省事）
```

```text

  不改代码；文档记录三条路线与 §6 的 fan_mode 缺口

有真机后
```

## 8 已知坑（选型前先看）

```text
涂鸦化机型     2021 年后部分美的/贴牌机型走涂鸦平台，美的协议系集成全部不适配；
              新型号可能沿用老型号名，购买前留退货空间
API v2         官方集成基于云端 API v1，部分新设备走 API v2，只能部分支持
抢设备         同一台设备同时接到两个集成会互相打架；设备同一时间只接受一个本地连接
凭据前提       设备先在手机 App 里绑定可见，云端才取得到 token/key
局域网发现     本机 HA 在 Docker Desktop NAT 里，DHCP/广播发现大概率收不到；
              手动填 IP + token/key 的 TCP 直连预计可行（待真机验证）
```

## 9 待验证清单（需真机）

```text
1  本机 HA 跑在 Docker Desktop bridge 网络（172.18.0.2），美的局域网自动发现依赖 UDP 广播，
   大概率跨不到宿主机 LAN；手动填 IP + token/key 的 TCP 直连预计可行，未实测
2  美的空调在官方集成 / midea_ac_lan 下到底生成 climate 还是 climate+fan，
   决定 §6 缺口走 A/B/C 哪条
3  API v2 新机型（2024 年后生产）的本地协议兼容度
4  掉线恢复行为，对照米家冰箱掉线 2 天的案例
```

## 二、主线 A：安全性问题（3 篇）

这一线的共同问题不是“听不懂”，而是“听懂之后不能乱来”：LLM 一旦接管设备，错误动作会直接作用到物理世界，个人数据也会离开家庭。三篇的威胁来源不同，因此防御点也不同。

```
安全线三篇防的是不同风险
  07 HomeLLaMA     数据出境：指令、用户画像、家庭配置被传云端
  11 DS-IA         实体幻觉：控制不存在的设备，或在鲁莽执行与
                   过度询问之间摇摆
  15 PromptShield  环境注入：电视语音、屏幕文字、旁听对话被当成指令，
                   同时又要防“过度防御漏掉真跌倒”
```

### 07 HomeLLaMA：隐私保护与个性化（IEEE TMC）

研究问题是云端大模型换个性化，需要把指令、用户配置、家庭配置交给远程服务器，在“诚实但好奇”的服务器威胁模型下可能泄露日常起居和个人偏好；本地小模型有能力却不足以生成满意响应，形成性能-隐私两难。论文给的例子是“让客人进来”这类不点名设备的指令：商用助手缺预定义指令-动作对难以处理，而把这类含家庭信息的请求传云端又有隐私风险。

方法核心是让本地小模型学云端大模型的本事，把多数隐私敏感查询留在设备端：HomeLLaMA 持续更新本地小模型与用户配置实现主动交互，只有本地响应不令人满意且用户明确同意时，才走可选的 PrivShield 隐私保护云服务。评测用自建 DevFinder 基准和 100 人用户研究，基线是对照云端大模型与商用泛化助手。结论是本地微调后的服务质量显著提升且保持个性化，同时敏感数据留在本地，隐私明显增强。

### 11 DS-IA：防幻觉执行与主动拒绝（arXiv）

研究问题是 LLM 变成具身智能体后，直接执行会实体幻觉（控制不存在的设备），而迭代式框架在“鲁莽执行”和“过度询问”之间摇摆。例子是“把没有的客厅灯打开”：直接生成动作就是幻觉，但确有歧义时又不应反复打断用户。

方法分两阶段：先由语义防火墙结合当前家庭状态过滤无效指令、消解模糊，再由房间→设备→能力的确定性级联验证器核查物理可行后才执行，把“高层意图理解”和“底层物理执行”分开。在 HomeBench 上精确匹配 58.56%，较基线提升超过 28%，无效指令拒绝率 87.04%；在 SAGE 上自主成功率从 42.86% 升到 71.43%，同时保留对确需澄清歧义的识别精确率。基线是 HomeBench/SAGE 及通用 LLM 方案。它同时做模糊消解，是 A/B 交叉，但论文落点在“该不该执行、执行前验证”，故归安全线。

### 15 PromptShield-Home：环境多模态提示注入防御（UbiComp Companion 短文）

研究问题是家庭代理用多模态 LLM 直接看视频、听音频后，环境里大量“看起来像指令”的信号——电视说“把灯关掉”、屏幕文字、旁听对话、便签——可能被误当成用户指令触发误操作；而防御过当又会漏掉老人跌倒这类真实紧急指令。论文用这对矛盾做例子：照做会误触发，过度拒绝则安全完成率崩掉。

方法贡献是试点基准加三层比较：场景覆盖受话人歧义、屏幕/音频注入、健康监测误触发、混合占用、合法指令等；比较传统检测器（L0）、单多模态 LLM 代理（L1）、多代理协调（L2）三个抽象层，以执行/阻断/询问三种风险决策评估。评测上先指出聚合准确率有误导（恒“永不行动”的预测器就有 82%），改分别报“不安全执行率”和“安全完成率”。结果：检测器过度执行，各种多模态配置过度拒绝且全部漏掉真实跌倒，二者正确集互补；总是选对层的预言机达到 94.1%，最佳单层只有 76.5%，而路由器尚未实现，94.1% 只是上限。结论是家庭代理安全应做学习型路由加传感器融合，简单用多模态 LLM 替换检测器解决不了问题。

安全线小结：

```

  数据出境   07          本地小模型+可选隐私云   自建合成数据，缺真实家庭长期部署
  幻觉执行   11          防火墙+确定性级联验证    依赖规则库，跨家庭泛化待验证
```

## 三、主线 B：模糊指令理解问题（6 篇）

这一线的输入是省略、隐式、不点名设备、依赖个人上下文的话，论文要把它们补全成明确动作、规则或计划。它们处理的“模糊”层次不同，正好拉开一条从规则到真实对话的光谱。

```
模糊发生在哪一层                论文
  规则文本背后的隐性意图         01 MvTAP（节能/安全等标签）
  增强型规则不会写               03 HomeGenii（带条件/脚本/API）
  一句欠明确的目标               09 Sasha（“让客厅舒适”）
  真实对话里的渐进省略           13 PEC-Home（“还是把灯开大点”）
  端侧即时模糊指令 + 数据         04 VCU-LLM、12 MiCU
```

### 01 MvTAP：TAP 规则的隐性用户意图预测（ESWA）

研究问题是 TAP 规则只表达“如果触发器，则动作”，读不出用户创建规则时的隐性意图。例子是“如果你离开家，则关闭空调”：显性需求是关空调，隐性意图是节能，只有按意图才能把跨功能的规则连起来。

方法用三个视图分别学表示（触发器-动作图的用户视图、描述文本的开发者视图、知识图谱的知识视图），Transformer 融合后做多标签意图分类。数据取自真实 IFTTT 的 50,067 条规则，IoT 相关去重后 1,923 条、12 类意图；基线覆盖单视图（TF-IDF/SBERT/TextCNN、多种 GNN）、知识图谱（DistMult/ComplEx/RKE）和多视图方法。结果准确率 76.79%、Micro-F1 80.35%，比最强多视图基线提升 19.28%；消融显示开发者视图（功能描述文本）最关键。它的输出是意图标签，还需要接执行模块，这是该文与其他模糊理解文的主要区别。

### 03 HomeGenii：检索增强生成增强型 TAP 规则（IMWUT）

研究问题是平台演进后的“增强型”TAP 规则带脚本、条件逻辑、计算和外部 API 调用，普通用户不会写，LLM 靠预训练知识加基础 RAG 也吃力。例子是要表达“湿度低于 40% 且是工作日早晨才启动加湿器”这类带条件与计算的规则，一次写对很难。

方法做“先聚类后检索”的规则库：从 IFTTT applet 分类法构建规则库，语义聚类后检索，再压缩最小化 token，以三种注入方式配合 GPT-5、Gemini-2.5 Pro、DeepSeek-R1 生成。评测用 20 场景 × 4 种信息条件 = 80 条提示，基线为无 RAG 与未聚类规则库。结果准确率从 14%（无 RAG）升到约 84%，语义聚类相对未聚类提升 27% 准确率、16% 检索成功率，上下文检索 F1 约 91%；同时给足“逻辑+上下文”时准确率可达 100%。

### 04 VCU-LLM：设备端提示高效的模糊指令理解（IMWUT）

研究问题是用户爱说“帮我降低客厅的温度”这类模糊指令，现有助手要么只认显式指令，要么把模糊指令丢给云端大模型（高延迟、隐私、成本）。方法把 LLM 放边缘设备本地做理解与控制计划生成，核心是提示高效：模糊指令知识检索只挑 prompt 里最相关的设备信息，自建 40,000+ 条模糊指令-控制计划对做 LoRA 微调，再做 KV 缓存定制加速端侧推理。

基线是云端 Llama-7B、GPT-4o、GPT-3.5 及迭代推理变体、端侧 HomeLLM-1.1B 等。结果控制计划质量平均提升 43.3%，时间开销比端侧基线平均降低 8.44×。它同时解决端侧部署问题，本质属于 B（听懂模糊话）与“上设备”的交叉。

### 09 Sasha：欠明确目标的创造性推理（ACM CCS）

研究问题是用户常说的是“让这里舒适”“帮我节能”这种欠明确目标，没点名设备与动作，系统要把“舒适”这类抽象概念与空间、设备、个人偏好关联起来。例子是“让客厅变得舒适”：人类会联想到温度、照明、音乐且因人而异，现有智能家居做不到这种跨概念推理。

方法先做实证基线研究（跨年龄段用户调查），定位 LLM 的行动计划质量与故障模式，再构建 Sasha：把目标变成可用设备的动作/自动化例程，锁定相关设备、纳入用户偏好，用迭代推理抑制“幻觉计划”和“锁定无关设备”。在测试家庭落地并做 N=7 用户研究。结果上没有统一基准数值，核心结论是 LLM 能创造性推理但有故障模式，Sasha 减少了误报和无关设备锁定。它与 C 类系统文（如 SAGE）的差别在于贡献点是“把欠明确目标推理出来”，执行层的完整闭环还要靠后续框架补齐。

### 12 MiCU：端到端智能家居指令理解（武汉大学 + 小米，arXiv）

研究问题是指令理解对精确表述行、对“让卧室变得舒适”这类模糊指令不行；通用 LLM 泛化好但缺领域数据、任务适配不足、成本高。方法先合成领域数据再两阶段训练：DevCmd 数据集用自动工作流从真实用户日志合成 5 万样本、28 类，Qwen3-4B 底座经课程学习、思维链监督微调、强化学习训练；MiCU-fast 变体把冗长设备描述压成特殊 token 降成本。

基线是传统基于规则的选择法与少样本 ICL 的流行通用大模型。结果相对规则法提升 28.29%、相对最佳大模型提升 20.01% 准确率；令牌压缩使 prompt 长度降 31.9%、准确率仅降 0.6%。在线数据：用户纠正率降 1.57%，人工审核准确率提升 32.05%。它同样把“模糊理解”和“低成本部署”绑在一起。

### 13 PEC-Home：渐进省略指令的解读（arXiv）

研究问题是人的对话会随共享上下文越说越省，如“还是把灯开大点”，但家庭助手无视这种省略，还叠加两种歧义：多用户对同一表述期待不同（指代歧义），用户偏好随时间/环境演变（意图歧义）。论文自建首个专测渐进省略指令的 PEC-Home 模拟家庭数据集，省略分 1~4 级，评测零样本提示、ICL、RAG 三种增强手段在 Mistral、Gemma-2、Qwen2.5、DeepSeek-V3、GPT-4o 等模型上的表现。

结论相当关键：没有模型能仅凭省略指令准确执行；RAG 有帮助但指令越省略效果越差，始终达不到完整指令水平；增大参数量只在等级 2 有用、等级 4 迅速失效；GPT-4o 在 ICL 下处理等级 4 还不如某些配 RAG 的小模型。这篇的贡献偏“问题暴露+数据集”，与 01/03 形成对照：规则级模糊已被大幅解决，对话级高度省略仍是开问题。

## 四、主线 C：综合性智能家居方案（8 篇）

这一线的论文不把“单一环节”当核心贡献，而是给出从输入到决策/执行/记忆/个性化的整体系统或框架，其中多数还刻意解决效率与个性化。判断句：论文若同时覆盖输入理解、决策执行（或推荐）、记忆与效率中至少两个环节，且卖点就是这套组合，就归 C。

### 05 GenX：多模态生成式体验的设备编排（IMX）

研究问题是设备编排繁琐且高度静态，日常任务要多次手动交互、缺上下文响应。例子是用户阅读时，系统自动编排：电视显示生成图像、音箱播放环境音、AR 设备投射匹配场景的 3D 全息图。方法由感知流水线、生成式界面控制、体验流水线三模块组成，视觉-语言模型解读用户对环境感知，按可用输出模态生成体验，并实时生成、执行源代码以处理意外。

评估是两个真实场景（餐饮、阅读）加 N=16 用户研究，用户感知积极但无自动化基线对照，属于研究-through-design。它覆盖感知→生成→编排→执行整链，是 C 类里“体验形态最广”的一篇，证据强度偏定性。

### 06 DevPiolt：智能家居设备操作推荐（武汉大学 + 小米，arXiv）

研究问题是设备操作推荐要处理复杂操作逻辑（多设备+顺序）和多样化偏好，且对次优建议敏感。例子是开空调前往往要先开电源插座、顺序不能反；有人固定时刻开窗帘，有人避免频繁开关空调。方法用“预训练+微调+直接偏好优化 DPO+置信度曝光控制”四步：先在设备操作数据上学 IoT 领域知识，再用 DPO 对齐个人偏好，最后过滤低质量推荐避免负面体验。

数据是小米多数据集约 9,000 次交互；基线是 CGC 与 DeepSeek。整体 EM-Acc/LM-F1/Rule 为 44.33/57.49/53.03，DeepSeek 为 32.97/44.68/41.45，CGC 为 19.95/17.72/23.48，相对最佳基线平均提升 95.5%/58.5%/54.0%。在线部署一季：日均 25.5 万用户、32.6 万条建议，独立访客设备覆盖率提升 21.6%、曝光接受率提升 29.1%。这是 C 类里证据最强的部署型论文。

### 08 IoTGPT：高效个性化智能家居自动化（ACM CHI）

研究问题是设备爆炸带来控制复杂度和用户疲劳，而基于 LLM 的方案因非确定性、高推理延迟/成本、有限个性化而不可靠、低效。方法模仿人类把指令拆成子任务并记忆复用：已学子任务被复用以减少 LLM 调用，抽象分层任务知识和“喜爱凉爽环境”这类设备无关偏好，让偏好可跨设备迁移。原型部署在三星 SmartThings 上。

与最先进基线对比：任务成功率最高提升 85.43%，延迟降 78.40%，成本降 44%；用户研究 N=15，认知负荷降低。它同时覆盖子任务理解、记忆复用、偏好抽象和效率，是“综合系统”的典型结构。

### 14 AdaHome：本地小语言模型自适应助手（arXiv）

研究问题是基于大模型的系统依赖重量级云端推理，资源受限环境低效、有隐私隐患，长期个性化支持也有限。方法不做一刀切复杂推理，而是意图感知规划框架动态分流：简单指令走简单提示组件、需理解指令走轻量推理组件，配合链式草稿（chain-of-draft）稳定决策；偏好适应从长期用户反馈学习，不需要改 prompt 或重训。

评测数据是 90 条指令（30 直接 + 30 间接 + 30 模糊，源自 Sasha 40 条与 SAGE 50 条），在统一小模型设置下复现 Sasha、SAGE、Harmony 做基线。结果直接指令精确匹配成功率 86.7%，延迟最多降 3×；模糊输入保持竞争力且成本更低；多轮偏好一致率 88%，提示增强基线仅 52.5%。它把意图理解、执行决策、端侧部署、偏好适应四条线焊成一个系统，是“跨线综合”的代表。

### 16 MemAura：面向智能环境的结构化上下文记忆（ACM IMWUT）

研究问题是智能环境个性化需要持久上下文记忆，但长期设备/传感器日志组织成本高，模型难从中提取行为模式与偏好。方法提供记忆管理系统：记忆图管理器组织上下文并快速检索，周期性模式预测器给定时间戳预测周期性行为，用户画像方案把指令转成明确意图单元、增量更新并遗忘高层画像。

数据是两个指令数据集，基线是 Vanilla（无记忆）与向量检索增强 RAG。GPT-4o 骨干达 100% 准确率、38~43% 个性化率；轻量本地模型最高 95% 准确率、平均最高 37.5% 个性化率；Vanilla 只有 28~56% 准确率、个性化率不高于 21%，向量 RAG 为 54~83%、不高于 25%。另有鲁棒性实验和 8 人用户研究。它的贡献是“记忆子系统”，支撑任何上层推理，与 14 的“免重训偏好适应”形成互补方案。

### 17 TaskSense：异构传感器系统的任务分配与翻译（ACM SenSys）

研究问题是智能家居/工厂装了大量异构传感器系统，手工预定义规则处理不了灵活任务，基于 LLM 的方法又不懂传感器系统的真实能力与数据依赖。方法提出传感器语言：自动把传感器能力与数据依赖翻译成 LLM 能理解的词汇和语法，先解释用户意图并检查可解性、验证依赖正确性，再按传感器数据可用性/质量/实时反馈动态调整执行计划。

部署在真实智能家居，覆盖 4 场景、9 种传感器系统、60+ API、170 项任务、5 种数据模态，用 GPT-4o、Claude-3/3.5 和两款开源模型共 6 种 LLM；基线是 HuggingGPT 与 Sasha。结果在相近 token 用量下规划准确率最高 2×，答案准确率提升 75%。它把“异构设备协调”做成系统方案，补齐了 C 类里缺少的一环。

### 18 SAGE：基于接地执行的智能家居代理（文件名标 ACM CHI；arXiv 2311.00772，2023）

研究问题是 LLM 有常识与通用知识，却缺用户、住宅、设备的具体信息；传统助手靠预定义例程、固定流程和手工设备代码，处理不了“打开梳妆台上的灯”这类自然设备指代、“调低我烘干机的屏幕亮度”这类按需读 API 的命令，或“提醒我在打开冰箱时把牛奶扔掉”这类持久命令。方法把用户请求变成一个由 LLM 控制顺序决策的行动序列：每个决策函数按“任务信息+工具指令+格式信息+输入+历史”组提示，让模型选工具、解析输出、把观察写回历史再继续，直到主动终止；工具分个性化、设备交互、监控、外部交互四类，设备交互先规划再按需抓取 API 文档执行，设备消歧用设备照片与 OpenCLIP 做视觉匹配，监控由 LLM 现场写条件代码并注册轮询。

评测用真实 SmartThings 家庭配置（2 电视、1 冰箱、1 洗碗机、4 灯）建 50 项自动判定任务，分个性化、意图解析、设备解析、持久性、指令链和直接指令六类，另留 10 项防提示过拟合；在 GPT-4、GPT-4-turbo、GPT-3.5-turbo、Lemur、Claude2.1 上对比 One Prompt 与 Sasha 两个基线。SAGE+GPT-4 成功率 75%，两基线约 30%；故障分析显示 GPT-4 的主要失败来自误解模糊指令，GPT-4-turbo 主要卡在 API 请求格式与工具参数。归 C 的原因：它把模糊意图理解、设备指代、个性化、持久监控、指令链装进同一个 LLM 智能体，是典型的“综合系统”，同时它的 50 任务数据又成为 AdaHome 的 90 条指令来源、DS-IA 的自主成功率对照环境，属于系统与基准的双角色论文。

### 19 HomeFlow：面向智能家居智能体训练的可验证数据飞轮（美的/北邮/东华/北大，arXiv 2606.01230）

研究问题是 LLM 智能体转向物理世界控制后，训练数据从哪里来：真实家庭多轮交互采集太贵且有隐私限制，纯文本角色扮演合成又缺物理环境验证，容易产出“看着合理但不可执行”的命令，且每场景只有单条线性轨迹，训练不出能澄清意图、做多轮推理的智能体。例子是“感觉有点闷”：智能体要按当前环境推断该调空调还是开窗通风，纯文本数据无法验证动作是否对应真实设备、能否在当前房间执行。

方法把数据生成、轨迹扩展和策略优化绑在同一个可验证仿真环境上：HomeEnv 提供结构化家庭状态、隔离执行沙箱和规则验证/动作审计，HomeMaker 按真实天气、户型、设备先验程序化生成多样化初始状态；Blueprint 把开放式意图编译成可执行布尔成功条件并经三重过滤，MCTS-Flow 用角色感知的非对称树搜索（智能体节点优先扩展）合成多轮可验证轨迹；之后先做 SFT，再做与动态用户模拟器和 HomeEnv 实时互动的逐步 RLVE，用“进度+最终成功+安全审计惩罚”的复合奖励对齐物理状态。评测自建 SmartHome-Bench（1,678 实例），分原子控制、组合控制、模糊意图、上下文多轮、个性化记忆五类任务。

结果上 HomeFlow-RL-4B/8B 整体成功率 84.60%/87.03%，8B 反超 GPT-5.5（85.80%）1.23 个百分点；SFT 相对同样本量角色扮演基线提升 5.88%/4.67%；消融显示完整 MCTS 数据合成的生成成功率最高（96.48% vs 纯角色扮演 86.33%），逐步 RLVE 优于只给终局奖励的变体。归 C 的原因：它不是补某一环，而是把“环境仿真—数据合成—策略训练—评测基准”做成一套完整飞轮，且自带基准与多任务能力覆盖，是系统级、训练级的综合方案；它同时与 11/18 这类“可执行智能体”和 4 个 bench 里的 HomeBench/SimuHome 形成上下游关系。

## 五、形态补充类：综述与短文/轻量原型

### 02 Edge LLM：全面综述与端到端路线图（CCF TPCCI 调研论文）

正文开头即标明“调研论文”，无自建系统与实验，因此不能用“基线对比效果”衡量它。它的价值在给出一条从设备端适配到高效推理的端到端工程路线：先做参数高效微调与联邦学习（个性化关键），再到推理三支柱——模型压缩（量化/剪枝/蒸馏）、架构设计（注意力变体）、运行时/系统优化（KV 缓存、推测解码、内存分页），最后给整体评估框架与应用盘点。这一路线正好框住本文件夹的落地型工作：04 VCU-LLM 做 KV 缓存与提示高效、14 AdaHome 做小模型分流、16 MemAura 做记忆管理，都可看作这条路线的实例。分类结论：它是 19 篇里唯一的综述，放进“综述/路线图”类单独看，不进入方法有效性对比。

### 10 LLM 个性化 UX：轻量原型评估（arXiv 预印本）

研究问题是自动化要适应每户设备与需求很难，多数系统只配高频简单场景，罕见需求没覆盖。方法提出一套 LLM 智能家居架构，用用户偏好与自然语言自动化状态驱动，并对比不同 LLM、提示风格与数据表示（JSON vs 自然语言）。评估在 11 个预定义场景上进行，没有真实用户研究和真实中间件部署，论文自己也把真机部署列为未来工作，因此归“短文/轻量原型”更合适；若按问题属性看，它贴近 C 类的个性化自动化，只是形态是探索性原型。

有效结论仍然可参考：带偏好的 Starling 7B Alpha 平均分最高提升 52.3%、处理时间降 35.6%；比不带偏好、更大的模型效果好 26.4%，处理时间约快 20×。这说明小模型配好偏好表示，能在大模型没偏好的场景反超。

补充一点：15 PromptShield-Home 从形态上看也属于短文/试点基准。本表把它留在主线 A，是因为它的研究问题（环境提示注入）就是安全本身；若改用“只看论文形态”的口径，安全线的正规方法文就剩 07 与 11 两篇。

三个总体判断：

其一，综合性系统方案已成为最密集的主线（8 篇），其中 SAGE、IoTGPT、AdaHome 等做“执行型系统”，19 HomeFlow 进一步把“数据—训练—评测”做成飞轮；模糊指令理解仍有 6 篇，说明“听懂用户”从规则级意图（01、03）推进到对话级省略（13）和训练数据覆盖（19 的 QT3/QT4），仍是系统能力的地基。其二，安全是数量最少、也最年轻的主线：07 侧重隐私、11 侧重执行验证、15 还停留在短文试点，正规方法文只有两篇，与 B/C 的成熟度差距明显。其三，好方法的形态是“跨线”：SAGE、DS-IA、VCU-LLM、MiCU、AdaHome、IoTGPT、HomeFlow 都证明，单把模糊理解做好不够，还要同时回答“能不能执行、上不上得了设备、记不记得住偏好、数据从哪来”。

这套方法文献与 `4个bench` 那边正好互为镜像：方法文几乎都自建数据、自选基线和自定指标（IFTTT 规则集、PEC-Home、DevCmd、HomeBench/SAGE、小米日志互不通用），没有一个统一可复现的对比平台来同时测“理解—执行—个性化—安全”。把三类方法的评测统一到同一基准上，既能补方法文的横评缺口，也能反过来检验基准本身的设计是否覆盖真实家庭需求。

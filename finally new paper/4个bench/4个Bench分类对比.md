# 智能家居 4 个 Benchmark 的分类与综合对比

## 一、为什么要分类

四篇基准都在证一件事：**现有基准测不出“真实家庭”里的难度**。但它们各自“真”的方向不同——有的强调指令本身错不错，有的强调环境状态在变，有的强调个性化。把四篇放到同一条“从静态映射到动态智能体”的轴上看，能清楚看出测评重心在哪。

```
                评测对象更“静态”                   评测对象更“智能体化”
                    │                                    │
                    ▼                                    ▼
   HomeBench         SimuHome           SMH-Bench        PersonalHomeBench
   (指令→动作映射)    (状态+时间交互)     (能力+复杂度分层)   (个性化+主动规划)
   ────────────────┼──────────────────────────────────┼──────────
   只验证指令翻译      验证状态/时间约束      验证组合/多设备   验证长期上下文+反事实
```

## 二、候选分类与最终选择

我试了 2、3、4 三种粒度，权衡后推荐 **3 类**（够表达差异，又不至于每篇自成一类）。

```
  粒度      分类结果                                                      评价
  ─────────────────────────────────────────────────────────────────────────
  2类  ①指令-动作验证（HomeBench）
       ②环境-状态交互（SimuHome/SMH-Bench/PersonalHomeBench）           太粗，把时间&个性化
                                                                        混在一起
  3类  ①指令-动作纠错：HomeBench
       ②可执行环境交互：SimuHome、SMH-Bench
       ③个性化长程智能体：PersonalHomeBench                           ★ 推荐
  4类  ①②③同上 + 把 SimuHome(时间/状态) 与 SMH-Bench(复杂度分层) 拆开      单篇成类，过度细分
```

## 三、分类结果

```
【第Ⅰ类】指令-动作纠错型
  ◆ HomeBench
  重点：把用户指令变成"对"的设备操作集合；无效指令要能识别/拒绝
  环境：静态虚拟环境，仅验证 API 调用序列
  规模：100 场景 / 17 万+ 指令，单设备到多设备

【第Ⅱ类】可执行环境交互型
  ◆ SimuHome              ◆ SMH-Bench
  重点：在"有状态、可执行"环境里查状态、核约束、调度时间、处理组合
  环境：Matter 模拟器(时间加速) / HomeEnv(状态可执行可验证)
  规模：600 回合(12类) / 1100 任务(7大类×22子类，8~135 台设备)

【第Ⅲ类】个性化长程智能体型
  ◆ PersonalHomeBench
  重点：长期上下文、部分可观测、偏好演变、主动规划、多模态
  环境：分阶段构建家庭(角色/设备/记忆/背景) + PersonalHomeTools 工具箱
  规模：可扩展；三反应式 + 两主动式任务
```

## 四、三类之间的综合对比

| 对比轴 | Ⅰ 指令-动作纠错（HomeBench） | Ⅱ 可执行环境交互（SimuHome / SMH-Bench） | Ⅲ 个性化长程（PersonalHomeBench） |
|---|---|---|---|
| 要测的能力 | 指令翻译正确性、无效指令识别 | 状态感知、约束满足、时间/调度、组合、复杂度 | 长期上下文推理、部分可观测、主动规划、偏好对齐 |
| 交互模型 | 一次给全上下文→静态输出 | 工具型智能体 iterativo 查状态后动作 | 工具型智能体 + 需要主动收集信息 |
| 是否状态验证 | 仅验证目标 API 序列 | 由模拟器/环境按状态迁移判成功 | 由工具箱 + 角色扮演裁判判质量 |
| 是否含时间演化 | 弱 | 强（SimuHome 核心；SMH-Bench 状态驱动） | 有（记忆随时间积累） |
| 是否含个性化记忆 | 无 | SMH-Bench 部分（偏好检索）；SimuHome 无 | 核心（人物记忆/偏好/背景） |
| 多模态 | 无 | SimuHome 无；SMH-Bench 无 | 有（视频接地、转录） |
| 首要瓶颈 | 上下文注意力错误 + 幻觉 | 动作前不验证状态 + 时间调度崩溃 | 从纯推理到工具执行大幅掉点；计划有效性崩溃 |
| 最佳模型成绩 | DeepSeek-R1 ALL 56.39 | SimuHome：GPT-4.1 仅 54%；SMH：Gemini-3.1-Pro 85.2% | GPT-4 大多数设置最好 |

### 四条横切结论

1. **瓶颈不在“知不知道”而在“查没查”**。第Ⅰ类死穴是“幻觉/注意力错误”，第Ⅱ类死穴是“执行前不验证状态”，第Ⅲ类死穴是“从纯推理切到工具调用就崩”——三者本质都是**模型不会用工具先把真实状态搞清楚再动手**。
2. **无效 / 不可行指令是通行短板**。HomeBench 的 GPT-4o 在多设备无效指令上 0.0%；SimuHome 的“设备存在但达不到目标”比“设备不存在”更难；SMH-Bench 的自动化/个性化类是最大瓶颈；PersonalHomeBench 的主动拒绝也难。
3. **环境复杂度是放大器**。SMH-Bench 从简单到复杂家庭，Gemini 95.3%→83.8%、Qwen3.5-9B 73.3%→46.7%；说明设备越多、房间越多，模型越不可靠，加模型救不了。
4. **规模化 ≠ 能力**。PersonalHomeBench 明确说“模型变大救不了工具交互差距”；SimuHome 连最强模型总成功率也只有 54%。都指向“交互层推理”而非“模型容量”才是短板。

## 五、对方法类研究的启示

三类基准对应的正是方法研究的三条主线：

```
  基准缺口            方法对策方向                        对应方法论文
  ──────────────────────────────────────────────────────────────
  指令纠错/无效识别   主动拒绝+环境锚定、模糊/省略意图理解       DS-IA、MiCU、PEC-Home
  可执行环境交互      端侧小模型+状态验证、传感器/设备编排        AdaHome、VCU-LLM、TaskSense、GenX
  个性化长程记忆      结构化记忆、用户画像、偏好对齐             MemAura、HomeLLaMA、IoTGPT、DevPiolt
```

结论：**benchmark 逼出来的三个坑（不验证状态、不会拒绝无效指令、记不住个性化偏好），正好是需要方法类研究去填的洞。**

# 智能家居 4 个 Benchmark 论文总结

本文件夹四篇论文都在回答同一个大问题：**现有的智能家居基准够不够“真”**——即能否逼出大模型在真实家庭里把用户意图、设备约束、时间关系、个性化偏好处理对的能力。四篇各自补了一个缺口，定位如下图。

```
         覆盖维度         HomeBench   SimuHome   SMH-Bench   PersonalHomeBench
  ---------------------------------------------------------------------------
  设备/指令规模多样        是          中          是(8~135台)     是(可扩展)
  无效/不可行指令          是(核心)     是          是            部分(主动拒绝)
  多设备组合              是(核心)     部分         是           是
  时间/调度/状态演替       弱          是(核心)     状态驱动      是
  环境模拟器            虚拟环境      Matter模拟器  HomeEnv模拟器  PersonalHomeTools
  个性化/长期记忆         无          无           是(部分)      是(核心)
  环境复杂度分层          无          无           简单/中/复杂    角色/设备/记忆
```

---

## 1. HomeBench：在智能家居中评估大语言模型（中国 2024 ACM CHI）

### 研究问题

之前评测只测能做的“单设备、合法指令”，但真实家庭既要处理**无效指令**（用户指令里有错或根本做不到），又要处理**同时控多台设备**。论文问：大模型到底能不能识别指令里的错、并在一句话里把多台设备调对？

例子（论文开头原例）：用户说“把水壶和卧室灯调一下”，家里只有空调和风扇具备制冷能力。LLM 要先推理出“水壶和灯都没有制冷功能”，于是改生成“只能打开空调和风扇”。再比如用户说“请帮我打开所有的门和窗户通风”，但家里根本没有可操作的门——正确行为是识别出这是**无效指令**，而不是硬编一个动作。

### 解决方法

构建并开源一个数据集 + 虚拟评测环境：

```
HomeBench 数据集
  100个智能家居场景 × 17万+条用户操作指令
  每个场景至少47台设备；每个任务涉及 1~10 台设备
  5类任务（VS/IS 单设备有效/无效，VM/MM 多设备，IM 多设备无效）
  配一个可定制的虚拟环境，设备状态与方法都嵌入 prompt
```

评测方法覆盖三档增强手段：**提示（prompt-based）**、**少样本上下文学习 ICL（取 4-shot）**、**检索增强生成 RAG**、**LoRA 微调**。指标用 **SUCC（指令执行成功率）** 和 **F1**。

### 实验效果

| 维度 | 结果 |
|---|---|
| 模型 | Mistral-7B、LLaMA3-8B、Qwen2.5(7B/32B/72B)、Gemma2(9B/27B)、DeepSeek-v3、GPT-4o、QWQ-32B、DeepSeek-R1、o1-mini、o3-mini 等 13 个大模型 |
| 基线 | 提示式 + 4-shot ICL，均嵌入设备状态/方法上下文 |
| 最差情况 | GPT-4o 在多设备无效指令(IM)上成功率 **0.0%** |
| 最佳整体(ALL) | DeepSeek-R1 56.39 SUCC / 40.96 F1 |
| RAG | 只按房间检索反而让原本擅长的任务掉点（长上下文、冗余信息误伤） |
| 微调 | LoRA 微调 Qwen2.5-7B 两轮后全面超过 GPT-4o-ICL，但 VM/MM 仍低于 70%；OOD 泛化稳定 |
| 根因 | 主要瓶颈是**上下文注意力错误 + 不忠实生成（幻觉）**，微调也救不回来 |

一句话：**当前最先进大模型在“无效多设备指令”上接近失效，微调能到高地但补不上推理正确性这块短板。**

## 2. PersonalHomeBench：个性化智能家居智能体评估（LG 2026 arXiv）

### 研究问题

已有 agent 基准大多在简化/泛化任务上测，看不出模型在一个**有长期上下文、部分可观测、偏好不断变化**的家里到底能不能干。论文问：基础模型作为“个性化家庭 agent”准备好了吗？

例子：家里有些信息模型一开始看不见（部分可观测），例如“帮我选个适合周末聚会的娱乐方案”，它必须先调工具去检索家庭记忆、人物偏好、设备能力，再给出建议；或者做反事实推理“如果我把客厅灯调暗，妈妈会觉得舒适吗”。这类任务不在纯文本提示里给全所有信息，逼模型主动“查”。

### 解决方法

分阶段构建家庭环境（角色 → 设备 → 记忆/背景 → 可选视频接地），再从环境里合成五类个性化任务：

```
PersonalHomeBench
  反应式(问答)：信息接地 IG / 反事实推理 CF / 多项选择 MC
  主动式(规划)：特征推荐 FR(排序问题) / 计划生成 PG(编排层级)
  PersonalHomeTools 工具箱：家庭信息检索 / 设备控制 / 情境理解
  双设置对比：纯推理（上下文直接给全） vs 工具型 agent（自己查）
```

指标：反应式用 **ACC**；FR 用 **MAP@1**；PG 用 **Role-Playing Judge(RPJ)** 打分（绝对/相对模式）+ **计划有效性**（可执行子步骤比例）。

### 实验效果

| 维度 | 结果 |
|---|---|
| 模型 | 11 个，GPT-4、GPT-4o、Gemini 2.5 Pro；Qwen3-30B-Instruct/Thinking、NemoTron3-Nano-30B-A3B、GPT-OSS-20B；Qwen3-4B / 4B-Thinking |
| 关键现象 | 从“纯推理”切到“工具型 agent”性能大幅下跌，反应与主动任务都跌；**有效工具交互是主要瓶颈**，模型变大救不了 |
| 反应式 | 纯推理下 IG/MC 多超过 85%；加工具后掉几十个百分点，IG/CF 最惨 |
| 主动式 | FR 掉得最少；PG 的**计划有效性在工具型 agent 下几乎所有文本模型崩溃** |
| 推理模式 | 显式推理帮助纯推理，但到 agent 设置里基本失效，有时反而更差 |
| 多模态 | 只提升纯推理下的反应式性能，对主动任务、工具/长程规划几乎无帮助 |
| 最强模型 | GPT-4 在多数设置中最好，但没有单一模型在各任务/模态全面占优 |

一句话：**规模化 ≠ 能力，瓶颈在“能不能稳定调工具/跟踪状态”，不在模型容量。**

## 3. SMH-Bench：环境接地的大模型智能家居智能体基准（中国 2026 arXiv）

### 研究问题

现有基准要么是“静态指令→API 映射”，要么是有限的模拟，都不验证**真实家庭里动态状态、多设备、个性化**下的推理与执行。论文问：LLM 能不能在真实家庭里可靠地推理、交互、行动？

例子：用户说“感觉有点冷，请把我常用房间的制热调到和昨晚一样的温度”。要完成它，agent 必须：查实时环境变量 → 翻对话历史取“昨晚温度”偏好 → 识别“常用房间”。这是纯静态 API 映射评测测不出来的组合推理。

### 解决方法

```
SMH-Bench 基准 = HomeEnv 模拟器 + 任务分层 + 双评测协议
  HomeEnv：有状态、可执行、可验证（随动作产生真实状态迁移来判成功）
  1,100 个人工审核任务，7 大类(TC1~TC7) × 22 细分子类
  环境复杂度分层：简单(8台) / 中等 / 复杂(135台，多房间)
  两种设置：
     DR 直接推理：给全局摘要直接输出
     EIA 环境交互智能体：ReAct，从部分可观测开始，逐步用工具查
```

### 实验效果

| 维度 | 结果 |
|---|---|
| 模型 | 13 个 LLM：Gemini-3.1-Pro/Flash、Claude-Sonnet-4.6、GPT-5.4、DeepSeek-V3.2、Qwen3.5-397B/9B/4B、GLM-5 等 |
| 最佳 | Gemini-3.1-Pro：EIA 85.2% / DR 83.5%；开源里 DeepSeek-V3.2 75.5% / 69.5% |
| 最难点 | TC4（自动化/个性化调度）是最大瓶颈，Gemini 也仅 64%（EIA），最小模型 Qwen3.5-4B 仅 21.3% |
| EIA vs DR | EIA 让开源/中端模型起飞（Qwen3.5-9B +15.1%、GLM-5 +10.9%）；但 GPT-5.4 反而是 DR 高 1.3%（EIA 多步级联误差） |
| 复杂度影响 | 家庭越复杂性能越差：Gemini 简单→复杂 95.3%→83.8%，Qwen3.5-9B 73.3%→46.7% |
| 思考消融 | DeepSeek-V3.2 去掉思考：DR 掉 18.3 分、EIA 只掉 7.3 分，说明工具能部分补偿思考 |

一句话：**模型能啃原子任务，但一碰上组合、歧义、状态驱动、个性化就崩；环境复杂度是持续的放大器。**

## 4. SimuHome：面向智能家居大模型智能体的时间与环境感知基准（首尔大学 2025 arXiv）

### 研究问题

智能家居 agent 要处理潜在意图、时间依赖、设备约束、调度，但业界缺“真能交互看结果”的模拟器 + 有挑战的基准。论文问：LLM agent 会不会在动作前确认状态、能不能协调时间相关操作？

例子：用户说“感觉闷”其实暗指加湿/湿度控制（潜在意图）；“洗碗机洗完了就开厨房灯”是时间依赖；“早晨播放音乐”是调度。这些都要 agent 先感知、再规划、再核对时间。

### 解决方法

```
SimuHome 模拟器（基于 Matter 国际标准，时间加速）
  容纳多房间布局、环境变量(温度/照度)、智能设备
  13 个工具 API；设备模拟会检查内部约束并反馈到环境
  GUI 可视化，可无限做反事实/边界压力测试
基准：600 回合 = 12 种查询类型(QT1~QT4) × 可行/不可行，人工验证
统一用 ReAct 框架驱动 11 个 agent
```

### 实验效果

| 维度 | 结果 |
|---|---|
| 模型 | GPT-4.1、Gemini-2.5-Flash/Lite、Llama-4、Qwen3-235B-A22B、Gemma-3-12B、GPT-4.1-nano 等 11 个 |
| 最强 | GPT-4.1 仅 **54%** 总成功率 |
| 环境感知 QT1 | 可行 >85%（多数前沿模型），不可行掉很多 |
| 显式 vs 隐式 | 显式命令(QT3) >84%，隐式(QT2) 只有 62~66% |
| 时间推理 QT4 | 最难：GPT-4.1 50%/46%/34%；不可行的矛盾时间更差 |
| 不可行约束 | “设备存在但操作达不到目标”比“设备不存在”更难；Qwen3-235B-A22B 在 QT4-3-IF 做到 48% |
| 错误类型 | 可行：环境感知/意图推断/设备控制/行动规划/时间推理；不可行：矛盾处理不当/矛盾盲视/LLM-Judge 误判 |

一句话：**连最强模型总成功率也只有一半，核心短板是“动作前可靠验证状态”和“时间/调度协调”。**

## 横向对比结论

把这四篇叠在一起，能清楚看到智能家居基准的演进方向。

```
    单设备->多设备          无效/不可行           时间/状态            个性化/记忆
HomeBench            ●核心              ●核心                ○                  ○
SimuHome             ●                  ●                   ●核心               ○
SMH-Bench            ●                  ●                   ●                  ●(部分)
PersonalHomeBench    ●                  ●(主动拒绝)           ●                  ●核心
```

共同结论有三条：

1. **无效/不可行指令是最普遍的死穴**。HomeBench 的 GPT-4o 多设备无效 0.0%、SimuHome 的最佳 54%、SMH-Bench 的 TC4 崩盘、PersonalHomeBench 从纯推理到工具大幅下跌，指向同一个根因。
2. **“先查清楚再动手”的能力缺口最大**。四个基准都发现模型不会在执行前调用工具验证真实状态，导致幻觉/错控设备。
3. **环境复杂度是放大器**。设备越多、房间越多、上下文越长，性能系统性下降；仅靠加大模型不能弥合。

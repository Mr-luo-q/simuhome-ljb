## 1. 四个部分

```text
A  ha_core_official\core                       官方 HA Core 源码，只读参考
        官方 CI 用它的 Dockerfile 构建镜像
        ▼
   容器 homeassistant  :8123                   HA 本体，跑官方镜像 2026.6.4
        ▲ 读配置
        │
D  D:\homeassistant\config                     Windows 上的文件夹，被挂载成容器里的 /config
        └─ custom_components\simuhome\         自定义插件，HA 里的 SimuHome 实体来自这里

   容器 ──HTTP 每 10 秒轮询──► B ──HTTP──► C

B  old_simuhome_bridge_project  :8010              桥接层：反代 + 操作日志
C  simuprocject\Simuhome_experiment  :8000     SimuHome 仿真本体：3 房间 / 15 设备
```

四项里只有 **B** 是自己写的工程代码，**A** 是官方源码，**C** 是仿真本体，**D** 是 HA 的配置目录，也就是容器外面那个装着 HA 全部家当的文件夹。

| 代号 | 路径 | 里面有什么 | 作用 | 参与运行 |
| --- | --- | --- | --- | --- |
| A | `ha_core_official\core` | 官方 Core 源码 + `Dockerfile`、`rootfs\`、`machine\`、`script\`、`tests\` | 查官方实现与接口；必要时自己构建镜像 | 否 |
| B | `old_simuhome_bridge_project` | `bridge\app.py`、`compose.yaml`、两个启动脚本、`logs\` | 起 HA 容器；把 SimuHome 的 HTTP API 包一层转发与日志 | 是 |
| C | `simuprocject\Simuhome_experiment` | `src\simulator\`（`domain`/`application`/`api`）、`home_full.json`、数据 | 仿真内核 + HTTP API，被控端 | 是 |

## 3. D 到底是什么：一个被挂进容器的文件夹

D 不是软件，也不在镜像里，就是 Windows 硬盘上的一个普通文件夹：

```text
Windows 侧   D:\homeassistant\config\
容器内       /config\
```

两者的对应关系写在 `old_simuhome_bridge_project\compose.yaml` 里，只有一行：

```yaml
services:
  homeassistant:
    image: ghcr.io/home-assistant/home-assistant:stable
    ports:
      - "8123:8123"
    volumes:
      - D:\homeassistant\config:/config     # 冒号左边 = 宿主机文件夹，冒号右边 = 容器内路径
```

读法：把宿主机的 `D:\homeassistant\config` 接到容器里的 `/config`。容器启动时由 Docker 完成这次挂载，HA 就把 `/config` 当成自己的家目录来读写。改宿主机上的文件，容器里立刻生效；反过来也一样，它们是同一个文件夹的两条路径。

文件夹里实际有什么（容器内 `ls /config` 的实测结果）：

```text
配置类   configuration.yaml、automations.yaml、scenes.yaml、scripts.yaml、secrets.yaml
状态类   .storage\（auth 账号、core.config_entries、core.entity_registry、core.area_registry）
         home-assistant_v2.db（recorder 历史数据库）
插件类   custom_components\simuhome\（让 HA 长出 SimuHome 实体的集成）、hacs
日志等   home-assistant.log、dashboards\、blueprints\、tts\
```

同一个文件的两条路径：

| Windows 侧 | 容器内 |
| --- | --- |
| `D:\homeassistant\config\configuration.yaml` | `/config/configuration.yaml` |
| `D:\homeassistant\config\custom_components\simuhome\sensor.py` | `/config/custom_components/simuhome/sensor.py` |
| `D:\homeassistant\config\home-assistant_v2.db` | `/config/home-assistant_v2.db` |

为什么要挂在外面：容器是一次性的，`docker compose down` 或换个镜像重建后，容器内部写的东西就没了。HA 的账号、实体、设备、历史、插件全在 `/config` 下，只有挂到宿主机目录才能在容器重建后保留下来。也就是说，**这个文件夹才是“家”，容器只是运行它的壳**。

关于叫法：Docker 把“直接挂宿主机目录”叫 bind mount（绑定挂载），把 Docker 自己托管的存储叫 volume。这里是前者。写成“配置卷”容易让人以为它是 Docker 托管的东西，本文档统一叫 **HA 配置目录（挂载为容器内的 /config）**。

和“工程不自包含”的关系：`old_simuhome_bridge_project` 里只有 compose、bridge 和脚本，真正让 HA 认识 SimuHome 的那段代码在 D 里（`custom_components\simuhome\`），只拷贝工程目录会漏掉它。

## 5. 官方源码（A）有什么用

```text
运行上不用它   官方已把源码打包成镜像发布，docker pull 就能跑
               镜像 3.38 GB，容器内源码路径 /usr/src/homeassistant/
查证上要用它   想知道官方怎么实现、有哪些接口、参数长什么样，只能翻源码

证据一  A 里有构建配方
        Dockerfile（COPY rootfs /、WORKDIR /usr/src、LABEL io.hass.type="core"）、
        Dockerfile.dev、.dockerignore、rootfs\、machine\、script\

证据二  容器里跑的就是这份源码
        docker exec homeassistant ls /usr/src/homeassistant
          → LICENSE.md、README.rst、homeassistant\、pyproject.toml、requirements_all.txt
        容器内版本 2026.6.4，本地 clone 是 dev 2026.7.0.dev0，差一个月
```

已经用它查实的例子：官方 MCP Server 挂在 `/api/mcp`、WebSocket 有 295 条命令、Assist 工具用 `name/area/floor` 定位而不是 entity_id。

只有一种情况它从“参考”变“必需”：你要改官方行为、自己 `docker build` 镜像。加功能的正规做法是写自定义集成，也就是 D 里的 `custom_components\simuhome`。

## 7. HA 的四种安装形态

| 形态 | 组成 | 本机 |
| --- | --- | --- |
| HAOS | 整套 Linux 系统镜像（Supervisor + Docker + Core + Add-ons） | 否 |
| Supervised | Debian + Supervisor | 否 |
| Container | 只有 HA Core 容器 | 是 |
| Core | pip / venv 直接跑 Python | 否 |

仓库也是分开的：`home-assistant/core`（应用本体，本机只有这个）、`home-assistant/supervisor`、`home-assistant/operating-system`（HAOS）、`home-assistant/frontend`。

后果：core 里的 `/api/hassio/*`（转发 Supervisor）在这台实例上用不了，没装 Supervisor，配置项里也没有 `hassio` 集成。

## 9. 已知缺口

| 缺口 | 表现 |
| --- | --- |
| 虚拟时间失效 | `/api/time` 返回键是 `now`，集成只找 `current_time` / `time` / `base_time`，实测 `sensor.virtual_time = unknown` |
| 只有 OnOff 控制面 | `switch.py` 只识别 `1.OnOff.OnOff`，空调温度、灯亮度、窗帘都控不了 |
| 无拓扑概念 | bridge 与集成都没有“房间连通 / 门开闭” |
| 无目标断言与时间推进 | 只有实体状态，`fast_forward_to` 没暴露给 HA |
| 10 秒轮询 | coordinator 固定 `DEFAULT_SCAN_INTERVAL = 10`，快进中间状态会被漏掉 |
| bridge 无鉴权 | 任意本机进程可打 8010 触发设备控制 |
| 路径硬编码 | `LOG_DIR` 写死盘符、上游写死 `127.0.0.1:8000` |
| 工程不自包含 | 自定义集成在 D 里，不在 B 里，只拷贝 B 会缺一半 |

# 18 电脑蓝牙接入本机 HA 的可行性分析（BLE 实测）

核对日期 2026-09-28。与 17 号（Zigbee）同一类问题：无线电怎么进 HA。

## 0. 结论

```text
不能直接让 HA 用电脑的内置蓝牙。原因：HA 跑在 Docker Desktop 的 Linux VM 里，
蓝牙集成要 Linux 侧的 BlueZ + D-Bus + 适配器；Windows 的蓝牙栈与之不通，
Docker VM 里既没有适配器，也没有 BlueZ/D-Bus，容器也没做蓝牙所需配置。

可行路线：
① ESP32 + ESPHome 蓝牙代理      20~40 元    官方推荐虚拟化场景；能读广播也能主动连接（可控制）
② Theengs Gateway 用电脑蓝牙     0 元        只读：被动广播解码 → MQTT → HA；不能控制设备
③ USB/IP 把蓝牙适配器塞进 VM     取决于硬件   理论可行，工程量大（Windows 会失去蓝牙、VM 缺 BlueZ/D-Bus）
```

## 1. 本机实测

```text
主机蓝牙        Intel(R) Wireless Bluetooth(R)，实例 ID USB\VID_8087&PID_0033（内置 USB 设备）
HA 容器         homeassistant（HA 2026.6.4），HostConfig.Devices = null
                cap_add = null（没有 NET_ADMIN / NET_RAW）
                mounts 只有 D:\homeassistant\config → /config（没有 /run/dbus）
HA 蓝牙集成     /api/config/config_entries/entry?domain=bluetooth 返回 []
                → 当前 HA 里连蓝牙集成实例都没有，没有任何扫描器
MQTT            本机 mosquitto.exe 在跑，:1883；HA 的 mqtt 集成已启用（Theengs 路线现成可用）
```

## 2. 为什么"直接接电脑蓝牙"不行

```text
HA 蓝牙集成的运行前提（官方 Container 要求）：
  - 容器加 cap_add: NET_ADMIN / NET_RAW
  - 挂载 D-Bus：-v /run/dbus:/run/dbus:ro
  - 宿主机（HA 所在的 Linux）有 BlueZ >= 5.43（推荐 >= 5.63）、dbus-broker、内核 >= 5.15.62
  - 适配器由宿主机 BlueZ 管理，HA 通过 D-Bus 使用它

我们的 Docker Desktop VM 不满足这套前提；Windows 的蓝牙栈走 WinRT，
与 Linux 的 BlueZ/D-Bus 不通。
官方对虚拟化场景的原话："A Bluetooth proxy is particularly interesting to users who
virtualize their instance, where the USB pass-through may cause additional problems."
```

## 3. 路线① ESP32 + ESPHome 蓝牙代理（推荐）

```text
做法    ESP32 开发板烧 ESPHome（bluetooth_proxy），接入家里 WiFi → HA 自动发现
成本    20~40 元
能力    ESP32 / RP2040(Pico W)：广播 + 主动连接（能读写 GATT，可控制 BLE 设备）
        BK72xx / LN882x、Shelly Gen2+、SMLIGHT SLZB-U：只能听广播，不能主动连接
固件    ESP32 主动连接需要较新 ESPHome（单连接 2022.9.3+，多连接 2022.11.0+）
建议    板子带外置天线、最好带以太网（官方说明：减少 WiFi 占用，蓝牙接收更稳）
```

## 4. 路线② Theengs Gateway（零硬件，用电脑蓝牙）

```text
原理    Windows 上跑 Python 服务，用电脑蓝牙被动扫描 BLE 广播，解码成 JSON → MQTT
安装    pip install TheengsGateway
启动    python -m TheengsGateway -H <broker地址> -u <用户名> -p <密码> -D 1
        （-D 1 = 打开 Home Assistant MQTT discovery，设备自动出现在 HA）
支持    LYWSD03MMC、CGDK2、CGP1W、H5075、TH1/TH2、CGH1、CGPR1、MiScale、MiFlora 等传感器
限制    只读。它解码的是广播包，不做 GATT 写入 → 不能开灯、不能按 SwitchBot 按钮
代价    Windows 上多一个常驻 Python 服务；扫描范围就是电脑蓝牙的范围
```

验收：MQTT 里出现 Theengs 的 topic；HA 出现对应 sensor 实体。

## 5. 路线③ USB/IP 把适配器塞进 Docker（不建议）

```text
理论   Docker Desktop 有官方 USB/IP 流程；内置 Intel 蓝牙是 USB 设备（VID_8087&PID_0033），
       usbipd 有机会把它 attach 进 Docker VM，再 --device 给容器
问题   1 attach 期间 Windows 自己的蓝牙会消失（耳机、鼠标都会断）
       2 Docker VM 里没有 BlueZ / dbus-broker，要自己补
       3 HA 容器要加 NET_ADMIN / NET_RAW 并挂 /run/dbus，还要改现有 compose
       4 每次重启要重新 attach
结论   技术上能拼出来，投入产出比远低于买一块 ESP32
```

## 6. DIY 兜底（不推荐作为主方案）

Windows 侧用 Python bleak 直接连 BLE 设备，把状态写进 MQTT、订阅命令 —— 能实现控制，
但等于自己做一个桥，实体建模和可用性都要自己维护。用于个别设备攻关可以，
不适合当通用接入层。

## 7. 与 v2 MCP 的关系

```text
路线② 进 HA 的是 MQTT sensor 实体 → 只能投影 current（观察 + check_goal）
路线① 进 HA 的可以是 light / switch / cover 等 → 主动连接的设备能进 8 动作
BLE 被动传感器（温湿度/门磁）天生只读；要"控制"，必须走路线①（或 DIY）
```

## 8. 建议

```text
想控制 BLE 设备（灯带/按钮/开关类）    → 路线①，ESP32 蓝牙代理（20~40 元）
只想读 BLE 传感器（温湿度/花盆/体重）  → 路线②，Theengs Gateway（0 元，先跑起来看效果）
两条一起用也不冲突：传感器走 Theengs，控制类设备交给 ESP32 代理
```

注意这里买的是"桥"不是"被控设备"：一块 ESP32 放在家里覆盖范围内，
所有 BLE 设备都通过它进 HA，不需要每台 BLE 设备配一个；
同时它在 HA 里还是一个 ESPHome 原生 API 设备，顺带覆盖 ESPHome 协议线。
ESP32 与这台笔记本怎么配合（USB 烧录 → WiFi 运行 → HA 填 IP）见
19 号文档《Matter 设备与 ESP32 接入本机 HA》。

# 20 树莓派部署 HA：方案与在本项目中的用法

核对日期 2026-09-29。接前面 17/18/19 号文档的"无线电怎么进 HA"问题：
如果换成树莓派，那些限制会怎么变。

## 0. 结论

```text
新装只有两个官方支持的选择：
① HA OS（官方推荐，树莓派首选）  Raspberry Pi Imager 直接刷；自带 Supervisor 与 apps（加载项）
② HA Container（Docker）        自己维护容器；适合要把我们自己的服务放同一台 Pi

不要用：Supervised / Core —— 官方 2025-05 公告废弃，2025.12 起不再支持
（原文：Core 是"自己跑 Python 环境"那种装法；Supervised 是"自己装操作系统再叠 Supervisor"）
```

## 1. 方案对比

| 方案 | 怎么装 | 维护方式 | 加载项（apps） | 适合场景 |
| --- | --- | --- | --- | --- |
| HA OS | Raspberry Pi Imager 选 Home Assistant 镜像刷入 | 系统与 HA、加载项一起升级 | 有：Matter、ESPHome Device Builder、Zigbee2MQTT、Mosquitto 等 | 默认首选；想少折腾 |
| HA Container | Raspberry Pi OS 64-bit + Docker，跑 homeassistant 容器 | 自己升级容器、自己管依赖 | 没有；用独立容器替代 | 要把自研服务放同一台 Pi |
| Supervised / Core | 已废弃 | 不再支持 | 无 | 不要新装 |

## 2. 硬件怎么配（官方口径 + 实践建议）

```text
主板      Raspberry Pi 5 或 Pi 4，官方要求至少 2GB 内存；实践建议 4GB 起（多跑加载项）
          32 位板（Pi 3、Zero 2 W 之类）属于被废弃的 32 位系统，新装不要选
存储      官方口径：A2 等级、≥32GB 的 microSD；
          实践建议：USB SSD 或 NVMe（HA 数据库频繁写，SD 卡容易磨损）
电源      官方电源（Pi 5 用 27W USB-C PD，Pi 4 用 15W 级别）；
          官方明确说电脑 USB 口供电不够，手机充电器很多也不合适
网络      安装时必须插网线；之后推荐继续用以太网（Wi-Fi 可用，
          但 Pi 的 Wi-Fi 与蓝牙是同一颗芯片，蓝牙设备多时优先有线）
散热      官方外壳带风扇，或至少加散热片
无线电    Zigbee / Thread 棒插 USB 2.0 口，或加一条 USB 延长线
          （USB 3.0 对 2.4GHz 有干扰，这是社区公认的坑）
```

## 3. 换成 HA OS 后，前面记的限制怎么变

```text
USB 直通   Linux 原生：ZHA / Zigbee2MQTT 直接选 /dev/ttyUSB0，Docker Desktop 的痛点直接消失
蓝牙       树莓派自带适配器可用（官方列为 known working；走 UART 总线，连接数多时性能有限）
           → BLE 设备可以直接进 HA，不必再依赖 ESP32 代理或 Theengs
Zigbee     USB 协调器直插即可；ZHA 内置，Zigbee2MQTT 有官方加载项
Matter     HA OS + Matter app 是官方唯一支持形态（把 HA 换成 HA OS 才谈得上买 Matter 设备）
Thread     需要边界路由器；官方 Connect ZBT-2 可做 Zigbee 或 Thread，
           注意它不能同时跑 Zigbee 和 Thread（官方 FAQ 明确说放弃多协议）
加载项     Mosquitto、ESPHome Device Builder、Zigbee2MQTT、Matter 都是一键装
```

## 4. 我们项目怎么搬（两种）

```text
方案 A（推荐）  Pi 刷 HA OS，专职当"HA + 无线设备"主机
                Windows 继续跑 SimuHome + 发布器 + v2 MCP
                MCP 只需要把 HA base_url 指到 Pi 的 IP（token 重发一个）
                MQTT 让 HA 连回 Windows 上的 mosquitto，或把 broker 挪到 Pi 的加载项
                好处：现有沙盒和 MCP 都不用动，Pi 只解决无线电接入

方案 B          Pi 刷 Raspberry Pi OS 64-bit + Docker，跑 HA Container + 我们全部服务
                --device /dev/ttyUSB0 直接可用（这是 Docker Desktop 做不到的）
                蓝牙要加 cap_add NET_ADMIN / NET_RAW + 挂 /run/dbus（要求见 18 号文档）
                Matter 仍属"自担风险的容器模式"（官方只支持 HA OS）
                好处：一台机器全搞定；坏处：没有加载项，Mosquitto / Z2M / ESPHome 都要自己维护
```

### 4.1 HA OS 会不会挡住外部 MCP（不会）

```text
结论：不会。v2 MCP 只用 HA 的公开 API，与安装方式无关：
  REST      /api/states、/api/services、/api/logbook
  WebSocket /api/websocket（设备/实体/区域注册表只有 WS 能读）
这三条通道 HA OS / HA Container / Supervised 都提供，端口都是 8123。

换到 Pi 之后 MCP 侧只改两处：
  1 config.yaml：ha.base_url 从 http://localhost:8123 改成 http://<Pi 的 IP>:8123
  2 在 Pi 的 HA 里新建长期访问令牌，填进 HA_TOKEN
代码零改动（client.py 只认 base_url + token）。

HA OS 唯一的限制：它是封闭系统，不能把我们的 Python MCP 直接装到 HA 主机上跑
（没有自由 pip/apt，加载项是受管容器）。想 MCP 与 HA 同机，走方案 B
（Raspberry Pi OS + Docker），代价是失去官方 Matter 支持与加载项。

网络前提：Pi 与 Windows 在同一网段（别跨访客网络/AP 隔离）；
broker 留在 Windows 时，Windows 防火墙要放行 1883；
先用 GET http://<Pi>:8123/api/ 确认返回 "API running."。
```

### 4.2 树莓派跑 HA Container 可行吗（可行，官方有专页）

官方页面 "Home Assistant Container on Raspberry Pi"
（home-assistant.io/installation/raspberrypi-other/）给了完整口径，
和 Linux 通用页一致；通用页还有一句直接的话：
"Docker Desktop will not work; you must use Docker Engine."

官方给 Pi 的 Compose 骨架：

```yaml
services:
  homeassistant:
    image: ghcr.io/home-assistant/home-assistant:stable
    network_mode: host          # 关键：容器直接用 Pi 的网卡，mDNS 发现正常
    privileged: true
    stop_grace_period: 60s
    restart: unless-stopped
    volumes:
      - /PATH_TO_YOUR_CONFIG:/config
      - /etc/localtime:/etc/localtime:ro
      - /run/dbus:/run/dbus:ro  # 蓝牙要用
    environment:
      TZ: Asia/Shanghai
    devices:
      - /dev/ttyUSB0:/dev/ttyUSB0   # Zigbee 棒；更稳的写法是 /dev/serial/by-id/...
```

```text
Zigbee / BLE 棒   官方："需要映射设备" → --device /dev/ttyUSB0:/dev/ttyUSB0
蓝牙              官方：挂 /run/dbus:ro + privileged（CLI 版就是 --privileged）
ARM64 小坑        若报 jemalloc "Unsupported system page size"，加 DISABLE_JEMALLOC=true

相比 HA OS 要接受的代价（官方页面明确提示）：
  apps（加载项）只有 HA OS 有 → Mosquitto / Z2M / ESPHome / Matter 都要自己跑容器
  Matter 官方只支持 HA OS，Container 的 matterjs-server 仍是 at your own risk
  系统、Docker、容器升级全部自己管

对我们更关键的好处：
  Linux 真机 + host 网络 + --device → USB/Zigbee/BLE 全部原生可用，
  mDNS 发现也不会像 Docker Desktop 那样被 NAT 挡住；
  我们整套服务（HA + MCP + SimuHome + 发布器 + Mosquitto + Z2M）可以同机编排
```

一句话取舍：要 Matter 的官方支持 → HA OS（MCP 留在外面走网络）；
要一台 Pi 全搞定 → Raspberry Pi OS 64-bit + Docker，Matter 自担风险。

## 5. 什么时候别选树莓派

```text
同价位的 x86 迷你主机跑 HA OS 性能更好、能塞更多加载项；
官方 HA Green 最省心。选树莓派的理由通常是体积、功耗、GPIO
（要做硬件项目才用得上），以及手里已经有现成的板子。
```

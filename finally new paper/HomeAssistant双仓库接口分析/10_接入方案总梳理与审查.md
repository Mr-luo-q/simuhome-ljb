### 2.2 数据流

```text
上行（状态）
  SimuHome /api/home/state ──HTTP 轮询──► 发布器 ──MQTT──► Mosquitto ──► HA（MQTT 集成）
  轮询节奏：活跃 1 秒 / 空闲 10 秒；数值带死区，开关一变就发

下行（控制）
  HA 服务调用 → MQTT set 主题 → 发布器 → SimuHome /api/devices/{id}/commands
  → 回读属性 → 发 state 主题 → HA 更新 → 事件写 simuhome/v1/events
```

### 2.3 主题契约（v1，已冻结）

| 主题 | 方向 | payload | retain |
| --- | --- | --- | --- |
| `homeassistant/switch/<device_id>/config` | 发布器 → HA | discovery 配置 | 是 |
| `homeassistant/sensor/<room>_<metric>/config` | 发布器 → HA | discovery 配置 | 是 |
| `homeassistant/sensor/simuhome_virtual_time/config` | 发布器 → HA | discovery 配置 | 是 |
| `simuhome/v1/<device_id>/state` | 发布器 → 所有 | `ON` / `OFF` | 是 |
| `simuhome/v1/<room>/<metric>` | 发布器 → 所有 | 数值（已换算） | 是 |
| `simuhome/v1/time` | 发布器 → 所有 | `2025-08-24 06:41:11` | 是 |
| `simuhome/v1/<device_id>/set` | HA → 发布器 | `ON` / `OFF` | 否 |
| `simuhome/v1/status` | 发布器 → 所有 | `online` / `offline`（LWT） | 是 |
| `simuhome/v1/events` | 发布器 → 所有 | 命令回执 JSON | 否 |

## 3. 反馈：过程复盘

### 3.1 走过的弯路（都已修，记录以免重犯）

```text
1  amqtt 的 retained 投递不按订阅过滤器走：订阅 zzz/none 也收到 49 条别人的保留消息
   → 换成 Mosquitto（同时补上账号密码）
2  discovery 的 device.identifiers 写成 ["simuhome", device_id]（两个独立标识）
   → 24 个实体全塌缩到一台设备；改成单元素列表 ["simuhome_<id>"] 才对
3  PowerShell 的 Set-Content -Encoding UTF8 写 BOM，Python 读出的用户名带 \ufeff
   → 认证一直失败；改成 UTF-8 无 BOM 写入
4  SimuHome 的温湿度是放大 100 倍的整数（2600 = 26.00 °C）
   → 忘了换算，HA 里显示 2600 °C；在 mapping 里加 scale
5  中文 name 被 slug 成拼音，实体 id 变成 sensor.living_room_ke_ting_... 
   → 统一改名，并改用 object_id + 英文 id
6  仓库白名单漏了 simuhome_mqtt_publisher，30 个文件一度不在版本控制里
   → 补白名单，这次教训促成了 source.md 登记机制
7  start/stop 脚本用命令行匹配进程，会把我自己的 PowerShell 命令行也匹配进去
   → 观察到一次重复启动的假象；脚本判重需要改成 PID 文件或端口占用检查
```

### 3.2 关键决策记录

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| MCP 形态 | 自建独立 MCP server，不用官方集成方案 | 好发布、工作量可见、不被 HA 版本绑死 |
| HA 接入方式 | MQTT discovery | 唯一能同时给设备/area、实体类型覆盖、推送、可录制 |
| broker | Mosquitto（弃 amqtt） | amqtt retained 泄漏；Mosquitto 是参考实现 |
| 监听与鉴权 | 仅 127.0.0.1 + 账号密码 | HA 容器经 host.docker.internal 表现为 127.0.0.1，够用且不暴露局域网 |
| 拓扑 | 跳过 | SimuHome 与 HA 两侧都没有房间连通语义，需要手写 edges |
| 旧链路 | 退役，不修 | 语义不完整（无设备/无 area）且要退役，修它是浪费 |

### 3.3 有效做法（值得继续）

```text
先实测再下结论      broker 延迟、内存、retained 泄漏、实体清单、LWT 都拿数字说话
```

### 4.4 风险登记

| 风险 | 影响 | 现状与对策 |
| --- | --- | --- |
| broker 口令与令牌落在本机文件 | 泄露后可控制仿真设备 | 都在 `_secrets\` 与 `broker\*.credentials.txt`，已 gitignore；HA 令牌建议项目结束后轮换 |
| 单实例假设 | 并发实验会串味 | 一个实验一个实例；要做并发时加 SessionScope |
| 无进程守护 | 崩溃后数据停更（实体变 unavailable，不会假数据） | 变 unavailable 是安全失败；需要常驻时再上 Windows 服务或计划任务 |
| 主题契约变更 | 改 v1 主题等于换一代实体 | 契约已冻结；要改就发 v2 并清理旧主题 |
| Windows 环境 | 脚本编码、路径大小写、服务混用等坑多 | 已踩过 3 个（BOM、服务残留、脚本别字）；后续统一用 UTF-8 无 BOM 与绝对路径 |

### 4.5 对 MCP 的意义

```text
现在就有底座的工具
  observe_home / inspect_room / inspect_device（读 HA 的 states 与注册表）
  execute_action（走 HA 服务调用 → MQTT → SimuHome）
  check_goal（对状态做条件判定）
  query_events（HA 的 logbook/history）

仍然缺的
  query_topology   两边都没有房间连通语义，需要手写 edges
  time_control     沙盒侧可快进，HA 侧只能真实等待（虚拟时间现在能读，但不能推进）
  memory           HA 无原生记忆，需要 MCP 侧自己存
```

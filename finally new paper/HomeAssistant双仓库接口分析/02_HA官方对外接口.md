# HA 官方对外接口

只写 HA 官方暴露的东西，不涉及自建 bridge 与 SimuHome。
依据：容器内 2026.6.4 源码（`/usr/src/homeassistant/`）+ 本地 dev 克隆（2026.7.0.dev0）。

## 1. 分了七类

```text
① HTTP REST          /api/*            请求-响应，最基础
② WebSocket          /api/websocket    订阅 + 调用，能力最全，容器里 293 条命令
③ 鉴权与授权          /auth/*、/.well-known/*
④ 对话 / 助手 / Intent                  把一句话变成设备动作
⑤ MCP Server         /api/mcp          官方内置，把 HA 的工具暴露给外部模型
⑥ MCP Client                           把外部 MCP 服务器的工具接进 HA
⑦ 集成级通道          webhook / homekit / emulated_hue / mobile_app / 媒体代理 …
```

默认鉴权：所有视图 `requires_auth = True`，头部带 `Authorization: Bearer <token>`；CORS 默认只放行 `https://cast.home-assistant.io`。带 `requires_auth = False` 的入口单独列在第 2.6 节。

## 2. 逐类说明

### 2.1 HTTP REST

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/` | 存活探测 |
| GET | `/api/core/state` | 核心状态（RUNNING / STARTING …） |
| GET | `/api/config` | 实例配置（名称、单位制、版本） |
| GET | `/api/states` | 全量实体状态 |
| GET / POST | `/api/states/{entity_id}` | 读单个实体 / 外部写入状态 |
| GET | `/api/events` | 事件监听器列表 |
| POST | `/api/events/{event_type}` | 触发事件 |
| GET | `/api/services` | 全部服务及其参数 schema |
| POST | `/api/services/{domain}/{service}` | 调用服务，真正执行设备动作 |
| GET | `/api/components` | 已加载集成列表 |
| POST | `/api/template` | 模板求值，可当条件断言 |
| GET | `/api/stream` | 事件流（SSE） |
| GET | `/api/error_log` | 错误日志 |

领域接口（按需用）：历史 `/api/history/period[/{datetime}]`、日志流水 `/api/logbook[/{datetime}]`、日历 `/api/calendars[/{entity_id}]`、摄像头与媒体 `/api/camera_proxy/*`、`/api/image_proxy/*`、`/api/media_player_proxy/*`、语音 `/api/tts_proxy/{token}`、`/api/stt/{provider}`、文件 `/api/image/upload`、`/api/file_upload`、清单 `/api/shopping_list*`、运维 `/api/backup/*`、`/api/diagnostics/*`、配置流 `/api/config/config_entries/*`。

### 2.2 WebSocket

入口 `/api/websocket`，按用途分组（数字为命令数级别，不是全部）：

| 组 | 代表命令 |
| --- | --- |
| 状态与执行 | `get_states`、`subscribe_entities`、`call_service`、`get_services`、`get_services_for_target`、`supported_features` |
| 事件与触发 | `subscribe_events`、`unsubscribe_events`、`fire_event`、`subscribe_trigger`、`subscribe_condition` |
| 房间 / 楼层 / 设备 / 实体注册表 | `config/area_registry/list`、`config/floor_registry/list`、`config/device_registry/list`、`config/entity_registry/list`、`config/entity_registry/get_entries` |
| 历史与统计 | `history/history_during_period`、`history/stream`、`logbook/get_events`、`recorder/statistics_during_period` |
| 对话与助手 | `conversation/process`、`conversation/agent/list`、`conversation/chat_log/subscribe`、`assist_pipeline/run` |
| 可见性 | `homeassistant/expose_entity`、`homeassistant/expose_entity/list` |
| 模板与校验 | `render_template`、`validate_config`、`test_condition` |
| 认证 | `auth/current_user`、`auth/long_lived_access_token`、`auth/refresh_tokens` |
| 系统与运维 | `system_health/info`、`logger/log_level`、`repairs/list_issues`、`backup/*` |

注册表类是 HA 里唯一的“空间信息”来源：area（房间）、floor（楼层）、device/entity 归属，但没有房间之间的连通关系。

### 2.3 鉴权与授权

| 方法 | 路径 | 鉴权 | 作用 |
| --- | --- | --- | --- |
| GET | `/auth/providers` | 免 | 登录方式列表 |
| POST | `/auth/login_flow[/{flow_id}]` | 免 | 登录流程 |
| POST | `/auth/token` | 免 | 授权码换 access / refresh token |
| POST | `/auth/revoke` | 免 | 撤销 token |
| POST | `/auth/link_user` | 需 | 关联用户 |
| WS | `auth/long_lived_access_token` | 需 | 生成长期令牌 |
| GET | `/.well-known/oauth-authorization-server` | 免 | 授权服务器元数据：`/auth/authorize`、`/auth/token`、`/auth/revoke` |
| GET | `/.well-known/oauth-protected-resource` | 免 | 保护资源元数据（MCP 客户端据此发现授权方式） |

两种取令牌方式：长期 Bearer Token（脚本与外部 agent 常用）、OAuth2 授权码（客户端自动走 `/.well-known` → `/auth/authorize` → `/auth/token`）。

### 2.4 对话 / 助手 / Intent

```text
POST /api/intent/handle        直接执行某个 intent，绕过语言模型
POST /api/conversation/process 交给对话代理处理一句话
WS   conversation/process      同上，长连接版
service conversation.process   服务调用版（text / language / agent_id / conversation_id）
WS   assist_pipeline/run       完整助手管线：STT → intent/LLM → TTS

两个官方扩展点
  conversation.async_set_agent()  让一个集成本身成为对话代理
  llm.async_register_api()        把一个工具面注册给语言模型
                                  （matter、zwave_js、mcp 三个集成就是这么做的）
```

### 2.5 集成级通道

| 集成 | 通道 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| webhook | `POST /api/webhook/{webhook_id}` | 免 | 预留回调入口，id 即凭据 |
| hassio | `/api/hassio/{path}`、`/api/hassio_ingress/{token}/{path}` | 视图免，内部判 admin | 转发 Supervisor；只有 HAOS/Supervised 形态有 |
| emulated_hue | `/api/{username}/lights` 等 | 免 | 把实体伪装成 Hue Bridge |
| homekit | `/api/homekit/pairingqr` + HAP 桥 | 免 | 暴露给 Apple Home |
| mobile_app | `POST /api/mobile_app/registrations` | 需 | 手机推送通道注册 |
| html5 / ios | `POST /api/notify.html5/callback`、`/api/ios/push` | 部分免 | 推送回调 |

### 2.6 免鉴权入口（安全相关）

```text
/api/webhook/{webhook_id}
/auth/providers、/auth/login_flow*、/auth/token、/auth/revoke
/.well-known/oauth-authorization-server、/.well-known/oauth-protected-resource
/api/onboarding/users
/api/image/serve/{image_id}/{filename}
/api/{username}/...          （emulated_hue 全套）
/api/homekit/pairingqr
```

### 2.7 官方没有暴露的能力

```text
拓扑        只能表达“谁属于哪个房间”，无法表达房间之间是否连通、门是开还是关
房间聚合    没有“读某个 area 的环境量”，只有各房间下的 sensor 实体
目标断言    没有“目标是否达成”的判定接口，只能用模板或自动化条件拼
时间推进    没有“推进到某时刻”，真机上只能真实等待
长期记忆    无原生记忆/画像存储，只能借 todo、shopping_list、input_*
动作约束    supported_features 与 device_automation/*/capabilities 是散装查询
```

## 3. HA 官方的 MCP

### 3.1 是什么

官方集成 `mcp_server`（quality scale: silver，`integration_type: service`，`single_config_entry: true`，依赖 `http` + `conversation`，`requirements: mcp==1.26.0 / aiohttp_sse==2.2.0 / anyio==4.13.0`）。作用：把 HA 的能力按 MCP 协议暴露给外部模型客户端。

### 3.2 传输与端点

| 端点 | 协议 | 细节 |
| --- | --- | --- |
| `POST /api/mcp` | Streamable HTTP（无状态） | 单请求单响应；要求 `Accept: application/json` + `Content-Type: application/json`；超时 60 秒；通知类消息返回 202 |
| `GET /mcp_server/sse` | SSE（旧协议） | 建立长会话，先推一条 `endpoint` 事件告知消息地址 |
| `POST /mcp_server/messages/{session_id}` | SSE 配套 | 客户端 POST 消息，响应经 SSE 回流；会话 ID 是 ULID |

每次请求新建一个 MCP `Server` 对象和一组内存流，不跨请求保存状态。

### 3.3 鉴权

视图走普通 HA 鉴权（默认需 Bearer）。外部 MCP 客户端可以走 OAuth：从 `/.well-known/oauth-protected-resource` 发现，再由 `/auth/authorize` → `/auth/token` 取令牌。

### 3.4 工具从哪来

```text
tools/list → llm.APIInstance.tools
tools/call → llm.APIInstance.async_call_tool()
```

也就是说，MCP 的工具面不是单独维护的，而是直接取所选 LLM API 的工具。默认选 `assist`（Assist API），所以工具就是 Assist 的 intent 工具；工具集随“被暴露给 Assist 的实体”动态增删——某个 domain 没有暴露实体，对应工具就不出现。调用时构造的上下文是 `device_id = None`，拿不到“你在哪个房间”这类设备侧信息。

### 3.5 工具清单（默认 assist API）

| 工具 | 语义 |
| --- | --- |
| `HassTurnOn` / `HassTurnOff` | 开 / 关设备（对锁有语义反转） |
| `HassSetPosition` / `HassStopMoving` | 窗帘阀门位置 / 停止 |
| `HassLightSet` | 亮度、颜色、色温 |
| `HassClimateSetTemperature` | 空调温度 |
| `HassFanSetSpeed`、`HassHumidifierSetpoint`、`HassHumidifierMode` | 风扇、加湿器 |
| `HassMediaNext/Previous/Pause/Unpause`、`HassMediaPlayerMute/Unmute`、`HassSetVolume`、`HassSetVolumeRelative`、`HassMediaSearchAndPlay` | 媒体 |
| `HassVacuumStart`、`HassVacuumReturnToBase`、`HassVacuumCleanArea` | 扫地机 |
| `HassLawnMowerStartMowing`、`HassLawnMowerDock` | 割草机 |
| `HassStartTimer`、`HassCancelTimer`、`HassCancelAllTimers`、`HassIncreaseTimer`、`HassDecreaseTimer`、`HassPauseTimer`、`HassUnpauseTimer`、`HassTimerStatus` | 计时器（设备支持时才出现） |
| `HassBroadcast` | 语音卫星广播 |
| `HassListAddItem`、`HassListCompleteItem`、`HassListRemoveItem`、`TodoGetItems` | 待办清单 |
| `HassShoppingListAddItem`、`HassShoppingListCompleteItem`、`HassShoppingListLastItems` | 购物清单 |
| `GetDateTime`、`CalendarGetEvents`、`script.<entity_id>` | 时间、日历、脚本 |
| `GetLiveContext` | 唯一的通用状态读取工具，返回被暴露实体的状态与关键属性 |

参数是 `name` / `area` / `floor`（三选一必填）+ 可选 `domain`、`device_class`、`preferred_area_id`、`preferred_floor_id`。定位靠 HA 内部的名字与区域匹配，**不是 entity_id**。

被官方排除、不进工具面的 intent：`HassGetState`、`HassClimateGetTemperature`、`HassGetWeather`、`HassToggle`、`HassNevermind`、`HassGetCurrentDate`、`HassGetCurrentTime`、`HassRespond`、`HassOpenCover`/`HassCloseCover`。

### 3.6 resources 与 prompts

```text
resources/list → 只有一个：homeassistant://assist/context-snapshot（当前上下文快照，text/plain）
                 仅当所选 API 带 GetLiveContext 工具时出现
prompts/list   → 一个 prompt，名字是 API 名，内容是 api_prompt（其中含被暴露实体的静态清单）
```

### 3.7 配置与扩展

```text
配置项    llm_hass_api，多选，默认 ["assist"]
          多选意味着“官方工具 + 自己的工具”可以同时出现在 tools/list 里
扩展方式  写一个自定义集成，实现 llm.API（工具名、参数 schema、async_call_tool），
          用 llm.async_register_api() 注册，然后在 MCP Server 配置里勾上它
          全程不改 core 源码
```

### 3.8 反方向：MCP Client

`components\mcp`：填一个外部 MCP 服务器地址（支持 OAuth2），coordinator 拉取工具列表后注册成 LLM API，ID 形如 `mcp-<entry_id>`，提示词是 “The following tools are available from a remote server named {name}.”。如果 MCP Server 的 `llm_hass_api` 也勾了它，这些外部工具会再被暴露出去。

### 3.9 本机实测（2026-09-16）

```text
容器 2026.6.4 里 /usr/src/homeassistant/homeassistant/components/mcp_server/ 存在，
  且 http.py 里 STREAMABLE_API = "/api/mcp"、SSE_API = "/mcp_server/sse" 均在
mcp_server/http.py 与 server.py 与本地 dev 克隆 SHA256 完全一致（版本无漂移）
配置项已存在并启用：domain=mcp_server，llm_hass_api=["assist"]，title="Assist"
```

### 3.10 局限

```text
工具面偏控制   工具几乎全是“执行动作”，通用查询只有 GetLiveContext 一个
无空间语义     没有拓扑、没有房间聚合；房间只是 area 注册表里的归属关系
无时间语义     没有“推进时间”，没有“等到某时刻”，只有 GetDateTime 与计时器
无目标断言     没有“目标是否达成”的接口
无记忆         没有长期记忆与画像
定位靠名字     参数是 name/area/floor，实体名可被用户改动、可能重名
上下文缺失     device_id = None，模型不知道“我现在在哪个房间”
受可见性限制   工具与状态都受“实体是否暴露给 Assist”约束
```

# 最终架构（基于实测）

本文是当前生效的架构基线，替代 01~10 里的过程性结论。所有数字与行为都是 2026-09-17 在
本机实测得到的，不是设计意图。过程记录、选型对比与早期方案分别留在 08/09/10 与 05/06。

## 1. 运行时架构（已上线）

```text
SimuHome API :8000 ──HTTP 轮询──► 发布器 ──MQTT──► Mosquitto :1883 ──► HA :8123
        ▲                            │                                   │
        └─────HTTP 命令 / 写属性──────┘◄────── 命令主题 set / set_mode / set_temp / set_percent
```

```text
数据源唯一     SimuHome → 发布器 → Mosquitto → HA；旧 bridge（:8010）已退役，未监听
broker         Mosquitto 2.0.20，仅监听 127.0.0.1:1883，账号密码认证（HA 与发布器都用 u'simuhome'）
HA             Container 形态，2026.6.4，:8123；集成 mcp_server 已启用（llm_hass_api=["assist"]）
发布器         轮询活跃 1 s / 空闲 10 s；变化驱动 + 死区；retained；LWT 发 offline
失败语义       发布器或 broker 掉线 → 全部实体变 unavailable；不保留假状态
```

## 2. 实体模型（实测）

```text
/api/states        44 个实体，其中 simuhome 25 个 = 9 switch + 2 climate + 1 fan + 13 sensor
device 注册表      21 台，其中 simuhome 16 台 = 12 台可控 + 3 台房间虚拟设备 + 1 台网关
area              3 个：living_room / kitchen / utility_room
可控设备分布       living_room 5（空调、主灯、侧灯、电视、净化器）
                  kitchen 3（灯、洗碗机、风扇）
                  utility_room 4（灯、洗衣机、烘干机、空调）
未接入的 3 台      窗帘、冰箱、冷冻柜——没有 OnOff 属性，当前不发布
```

映射链与命名规则（写实现必须按这张表，不能靠字符串切分）：

```text
entity → device_id → area_id
  实体自身的 area_id 全是 None，房间只能从 device 取
  device_id 前缀不可靠：utility 房间的设备叫 utility_ac / utility_light，
  与 living_room_* / kitchen_* 的写法不一致

unique_id（发布器写死）
  switch.simuhome_<device_id>        ← unique_id 是 simuhome_<device_id>_switch
  climate.simuhome_<device_id>       ← unique_id 是 simuhome_<device_id>_climate
  fan.simuhome_<device_id>           ← unique_id 是 simuhome_<device_id>_fan
  sensor.simuhome_<room>_<metric>    ← unique_id 同名
  sensor.simuhome_virtual_time       ← unique_id 同名

entity_id
  HA 的 MQTT discovery 不支持 payload 里的 object_id（2026.6 源码无该常量），
  id 会按「区域 + 设备名 + 实体名」自动生成，例如 climate.living_room_air_conditioner_air_conditioner；
  规范 id 由 publisher\rename_entities.py 用 WebSocket config/entity_registry/update 强制，
  脚本幂等，实体重建后重跑一次即可
```

## 3. 主题契约 v1（冻结）

| 主题 | 方向 | payload | retain |
| --- | --- | --- | --- |
| `homeassistant/switch/<device_id>/config` | 发布器 → HA | discovery 配置 | 是 |
| `homeassistant/climate/<device_id>/config` | 发布器 → HA | discovery 配置 | 是 |
| `homeassistant/fan/<device_id>/config` | 发布器 → HA | discovery 配置 | 是 |
| `homeassistant/sensor/<room>_<metric>/config` | 发布器 → HA | discovery 配置 | 是 |
| `simuhome/v1/<device_id>/state` | 发布器 → 所有 | `ON` / `OFF` | 是 |
| `simuhome/v1/<device_id>/mode` | 发布器 → 所有 | `off` / `cool` / `heat` | 是 |
| `simuhome/v1/<device_id>/target_temp` | 发布器 → 所有 | 摄氏度 | 是 |
| `simuhome/v1/<device_id>/current_temp` | 发布器 → 所有 | 摄氏度（设备温度计） | 是 |
| `simuhome/v1/<device_id>/percent` | 发布器 → 所有 | `0`~`100` | 是 |
| `simuhome/v1/<room>/<metric>` | 发布器 → 所有 | 数值（已换算） | 是 |
| `simuhome/v1/time` | 发布器 → 所有 | 虚拟时间字符串 | 是 |
| `simuhome/v1/<device_id>/set` | HA → 发布器 | `ON` / `OFF` | 否 |
| `simuhome/v1/<device_id>/set_mode` | HA → 发布器 | `off` / `cool` / `heat` | 否 |
| `simuhome/v1/<device_id>/set_temp` | HA → 发布器 | 摄氏度 | 否 |
| `simuhome/v1/<device_id>/set_percent` | HA → 发布器 | `0`~`100`（0 等于关机） | 否 |
| `simuhome/v1/status` | 发布器 → 所有 | `online` / `offline`（LWT） | 是 |
| `simuhome/v1/events` | 发布器 → 所有 | 命令回执 JSON | 否 |

命令回执字段：`{device_id, command, payload, steps, ok, ms, ts}`；失败时多一个 `error`。
`steps` 记录真实发生的每一步，例如空调开制冷是 `["On", "SystemMode=3"]`——档位类属性有上电依赖，
发布器会先补一条开机并把这一步暴露出来，不做隐式修改。

## 4. 设备能力矩阵（当前）

```text
HA 域          动作                                                      SimuHome 落点
switch         turn_on / turn_off / toggle                              OnOff 命令（9 台）
climate        set_mode(off|cool|heat)                                  OnOff + Thermostat.SystemMode（2 台）
               set_temperature(7.00~32.00，步长 0.5)                     OccupiedCooling/HeatingSetpoint（0.01°C 整数）
fan            turn_on / turn_off / set_percentage(0~100)               OnOff + FanControl.PercentSetting（1 台）
sensor         只读                                                     房间温度/湿度/照度/PM10、虚拟时间
```

物理效应速率（读 `aggregators/temperature.py` 得到，决定了任务时间尺度）：

```text
空调制冷   速率 = min(0.0005, 温差°C × 1.0) × 风速百分比 ÷ 100  °C/s
           满风、温差 ≥1 °C 时约 0.0005 °C/s = 1.8 °C/h
风扇降温   速率 = min(0.0002, 温差°C × 0.5) × 档位 ÷ 100  °C/s
           满档约 0.0002 °C/s = 0.72 °C/h，目标是降到「基线 − 2 °C」
含义       "20 分钟内降温 3 度"这类任务在真实时间轴上不可能达成，
           只能在沙盒侧用快进跑；HA 侧的时序任务必须用秒级窗口
```

## 5. MCP server 架构（下一步实现）

分层与目录沿用 05：`entry.py`、`server.py`、`errors.py`、`runtime.py`、
`contract\`（tools / conditions / clock / sinks）、`backend_ha\`（client / mapping / tools\ 八个）。
依赖规则不变：`entry → server → contract`，`entry → backend_ha → contract, runtime`，
`backend_ha` 不许 import `server`，`contract` 只用标准库。

ToolSpec 是唯一语义来源（出处见 `UbiComp三支柱讨论\8_统一语义接口架构与伪代码.md`），
冻结时每个工具要有五个字段，而不是探针里的三个：

```text
name            工具名
params          参数 schema
returns         返回结构
errors          允许抛出的错误码集合     ← 探针里缺
time_semantics  这次调用消耗的是虚拟时间还是真实时间 ← 探针里缺
maps_to         论文口径的名字（wait_for_event / check_goal_state / memory_read…），统计用
```

后端映射规则（全部来自实测，写实现时照抄）：

```text
建表      启动时读 WS config/entity_registry/list + config/device_registry/list，
          生成 {device_id → entity_id, domain, area_id, kind, unique_id}；
          实体自身 area_id 为 None，务必经 device 取
能力      主体 = get_services_for_target 的服务名列表，但要按 domain 白名单过滤
          （它会返回 homeassistant.reload_config_entry 这种管理员服务）；
          参数 schema 从 REST /api/services 补；supported_features 对 switch 返回 null，不用
动作      规范动作 → HA 服务：switch.turn_on / climate.set_temperature / fan.set_percentage；
          无对应服务时返回 UNSUPPORTED_ACTION
目标      check_goal 的目标命名空间：<room>.<metric>（环境量）与 <device_id>.<attribute>（设备属性）
事件      query_events 走 logbook，默认排除 sensor.simuhome_virtual_time（实测占 91%）
可用性    调用前读状态，unavailable / unknown 直接返回 DEVICE_UNAVAILABLE，
          不要发服务调用——MQTT 实体掉线时 HA 仍会把命令发进主题，会得到假成功
回读      verify_delay_ms = 500、attempts = 3（实测一次命令 + 回读 280~388 ms）
```

## 8. 决策记录（2026-09-17）

| 决策 | 选择 | 理由 | 落地结果 |
| --- | --- | --- | --- |
| 档位设备 | 空调 → climate，风扇 → fan，其余保持 switch | 空调是空间传播任务的主角，风扇提供百分比档位；两者属性在 SimuHome 里已存在 | 已上线，2 climate + 1 fan + 9 switch |
| 旧实体处理 | 转换时向旧 switch discovery 主题发空 payload | 同一设备挂两个实体语义重复 | 3 个旧 switch 已删除 |
| entity_id | 用 rename_entities.py 强制规范名 | MQTT discovery 不支持 object_id | 3 个实体已改名 |
| 房间归属 | 只从 device.area_id 取 | device_id 前缀不可靠 | 写入 05 的实现要点 |
| 回读参数 | verify_delay_ms=500 | 实测 280~388 ms | 写入 05 §8 |
| 快进 | 本轮暂缓 | 用户决定，先把桥接与接口做扎实 | 仅记录事实，不进实现 |
| 仪表盘 | 3 个实体 id 同步替换 | 实体类型变了 | dashboards/simuhome-dashboard.yaml 已更新 |
